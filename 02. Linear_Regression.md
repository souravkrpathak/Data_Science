## 1. Core Concepts

### What is Linear Regression?

Linear Regression is a **supervised learning algorithm** used for predicting a continuous target variable based on one or more input (predictor) variables. It models the relationship between the dependent variable $y$ and independent variable(s) $X$ as a **linear combination** of the inputs.

**Purpose:**
- Predict a continuous numeric outcome (e.g., house price, salary, temperature).
- Quantify and interpret the strength/direction of relationships between variables.
- Serve as a baseline model before trying more complex algorithms.
- Perform inference — understanding *which* features matter and *how much*.

### Mathematical Formulation

**Simple Linear Regression** (one predictor):

$$
y = \beta_0 + \beta_1 x + \epsilon
$$

- $y$: dependent/target variable
- $x$: independent/predictor variable
- $\beta_0$: intercept (value of $y$ when $x = 0$)
- $\beta_1$: slope (change in $y$ per unit change in $x$)
- $\epsilon$: irreducible random error term, assumed $\epsilon \sim N(0, \sigma^2)$

**Multiple Linear Regression** (multiple predictors):

$$
y = \beta_0 + \beta_1 x_1 + \beta_2 x_2 + \dots + \beta_p x_p + \epsilon
$$

**Matrix / Vectorized form** (used in practice and in derivations):

$$
\mathbf{y} = \mathbf{X}\boldsymbol{\beta} + \boldsymbol{\epsilon}
$$

where:
- $\mathbf{y}$ is an $n \times 1$ vector of observed outcomes
- $\mathbf{X}$ is an $n \times (p+1)$ design matrix (first column of 1's for the intercept)
- $\boldsymbol{\beta}$ is a $(p+1) \times 1$ vector of coefficients
- $\boldsymbol{\epsilon}$ is an $n \times 1$ vector of errors

**Goal:** Find $\hat{\boldsymbol{\beta}}$ that minimizes the discrepancy between predicted values $\hat{y} = X\hat\beta$ and actual values $y$.

**Closed-form (Ordinary Least Squares) solution:**

$$
\hat{\boldsymbol{\beta}} = (\mathbf{X}^T\mathbf{X})^{-1}\mathbf{X}^T\mathbf{y}
$$

This is called the **Normal Equation** — it directly gives the coefficients that minimize squared error, without iterative optimization (though it requires $\mathbf{X}^T\mathbf{X}$ to be invertible).

## 2. Cost Function — Mean Squared Error

### Why do we need a cost function?

We need a quantitative way to measure "how wrong" a given set of coefficients $\beta$ is, so we can search for the $\beta$ that minimizes that wrongness.

### Mean Squared Error (MSE)

$$
J(\beta) = \text{MSE} = \frac{1}{n}\sum_{i=1}^{n}(y_i - \hat{y}_i)^2 = \frac{1}{n}\sum_{i=1}^{n}\left(y_i - (\beta_0 + \beta_1 x_i)\right)^2
$$

**Why squared error (and not absolute error)?**
1. **Differentiability** — squared error is smooth and differentiable everywhere, enabling calculus-based optimization (gradient descent / normal equations). Absolute error has a non-differentiable kink at zero.
2. **Penalizes large errors more** — squaring disproportionately punishes big mistakes, pushing the model to avoid large deviations.
3. **Convexity** — MSE as a function of $\beta$ is a convex paraboloid, guaranteeing a single global minimum (no local minima to get stuck in).
4. **Statistical justification** — minimizing squared error is equivalent to Maximum Likelihood Estimation (MLE) of $\beta$ under the assumption that errors are i.i.d. Normally distributed (shown below).


### Interpretation
- MSE is in **squared units** of $y$ (e.g., "rupees²"), which is hard to interpret directly — this is why **RMSE** (square root of MSE) is often reported, since it's in the same units as $y$.
- **R² (coefficient of determination)** is a normalized, scale-free version:

$$
R^2 = 1 - \frac{\text{SS}_{res}}{\text{SS}_{tot}} = 1 - \frac{\sum(y_i - \hat y_i)^2}{\sum(y_i - \bar y)^2}
$$

  $R^2$ tells you the proportion of variance in $y$ explained by the model (0 = no better than predicting the mean; 1 = perfect fit). **Adjusted R²** penalizes adding useless predictors, since plain $R^2$ never decreases when you add more features.

## 3. Assumptions of Linear Regression

OLS regression coefficients are only the **Best Linear Unbiased Estimators (BLUE)** — per the Gauss-Markov theorem — when certain assumptions hold. Violations don't always break the model, but they undermine reliability of coefficients, p-values, and predictions.

| # | Assumption | What it means | How to check |
|---|-----------|----------------|---------------|
| 1 | **Linearity** | The relationship between each predictor and the target is linear (in the parameters) | Scatter plots of $y$ vs each $x$; residuals vs fitted plot should show no curve |
| 2 | **Independence of errors** | Residuals are not correlated with each other (no autocorrelation) — crucial for time-series data | Durbin-Watson test; residuals vs order/time plot |
| 3 | **Homoscedasticity** | Constant variance of errors across all levels of predictors (no "funnel" shape) | Residuals vs fitted plot; Breusch-Pagan / White test |
| 4 | **Normality of residuals** | Errors are normally distributed (mainly needed for valid p-values/CIs, not for point estimates) | Q-Q plot; Shapiro-Wilk test; histogram of residuals |
| 5 | **No/low multicollinearity** | Predictors are not highly linearly correlated with each other | VIF, correlation matrix |
| 6 | **No endogeneity** | Predictors are uncorrelated with the error term (exogeneity) — otherwise estimates are biased | Domain knowledge; instrumental variables if violated |
| 7 | **X is measured without error** | Predictors are fixed/deterministic or measured precisely | Rarely testable directly; a modeling assumption |

### Detail on each core assumption

**1. Linearity**
The model assumes $E[y|X] = X\beta$. If the true relationship is quadratic, exponential, etc., a straight-line model will systematically under/over-predict in certain ranges. **Fix:** add polynomial/interaction terms, transform variables (log, sqrt), or use non-linear models.

**2. Independence of Errors**
If residual at time $t$ correlates with residual at $t-1$ (common in time series), standard errors are underestimated, making p-values look more significant than they really are. **Fix:** add lagged terms, use time-series-specific models (ARIMA), or use Newey-West standard errors.

**3. Homoscedasticity**
If error variance grows with the predictor value (a "megaphone" shape in residual plots), OLS coefficients stay unbiased, but standard errors become invalid, so confidence intervals and hypothesis tests are unreliable. **Fix:** transform $y$ (e.g., log), use Weighted Least Squares (WLS), or use heteroscedasticity-robust standard errors.

**4. Normality of Residuals**
This assumption is required mainly for the **inferential** parts of the model — valid t-tests, F-tests, p-values, and confidence intervals — not for the point estimates themselves (by Gauss-Markov, OLS is BLUE regardless of the error distribution, given the other assumptions). With large samples, the Central Limit Theorem makes this assumption less critical.

**5. No/Low Multicollinearity**
Discussed in depth in [Section 5.1](#51-multicollinearity--vif).

## 4. Model Evaluation

### 4.1 Residual Analysis

The **residual** for observation $i$ is $e_i = y_i - \hat y_i$. Since residuals are the "leftover" signal the model didn't capture, they are the primary diagnostic tool in regression.

**Key plots and what to look for:**

| Plot | Purpose | Red flag pattern |
|------|---------|-------------------|
| **Residuals vs Fitted values** | Check linearity & homoscedasticity | Curve → non-linearity; funnel → heteroscedasticity |
| **Q-Q Plot (Quantile-Quantile)** | Check normality of residuals | Points deviating from the 45° line, especially at tails |
| **Scale-Location plot** (√\|standardized residuals\| vs fitted) | Check homoscedasticity more clearly | Upward/downward trend in spread |
| **Residuals vs Leverage** | Identify influential points | Points far right with large residuals (high Cook's Distance contours) |
| **Residuals vs Order/Time** | Check independence (autocorrelation) | Cyclical or trending pattern |

**Standardized vs Studentized residuals:** Raw residuals can be misleading because their variance differs depending on leverage. **Standardized residuals** divide by an estimate of their standard deviation; **studentized (deleted) residuals** go further, refitting the model without observation $i$ to compute a more robust measure — these are better for outlier detection since an extreme point doesn't inflate its own denominator.

### 4.2 Statistical Significance of Coefficients

Once we have $\hat\beta$, we want to know: **is each coefficient meaningfully different from zero, or could it be due to random noise?**

**Standard Error of a coefficient:**

$$
SE(\hat\beta_j) = \sqrt{\hat\sigma^2 \left[(X^TX)^{-1}\right]_{jj}}
$$

where $\hat\sigma^2 = \frac{\text{RSS}}{n-p-1}$ is the estimated error variance.

**t-statistic** — tests $H_0: \beta_j = 0$ vs $H_1: \beta_j \ne 0$:

$$
t_j = \frac{\hat\beta_j - 0}{SE(\hat\beta_j)}
$$

This follows a t-distribution with $n-p-1$ degrees of freedom under $H_0$.

**p-value:** The probability of observing a t-statistic at least as extreme as the one calculated, *assuming the null hypothesis (no real effect) is true*.
- **Small p-value (< 0.05 typically)** → strong evidence against $H_0$ → coefficient is likely statistically significant (real relationship).
- **Large p-value** → insufficient evidence that the predictor has an effect on $y$ — it might just be noise.
- **Important nuance:** statistical significance ≠ practical significance. With huge sample sizes, even a tiny, meaningless coefficient can be "significant."

**Confidence Interval for $\beta_j$** (typically 95%):

$$
\hat\beta_j \pm t_{\alpha/2, \, n-p-1} \cdot SE(\hat\beta_j)
$$

Interpretation: if we repeated the sampling/estimation process many times, 95% of such intervals would contain the true population coefficient. If the CI does **not** contain 0, this is consistent with (and equivalent to) rejecting $H_0$ at that significance level.

**F-statistic (overall model significance):** Tests whether *at least one* predictor has a non-zero coefficient — i.e., whether the model as a whole is better than just predicting the mean of $y$.

## 5. Addressing Model Issues

### 5.1 Multicollinearity & VIF

**Definition:** Multicollinearity occurs when two or more predictors in the model are highly linearly correlated with each other. This doesn't bias the predictions of the model overall, but it destabilizes individual coefficient estimates.

**Consequences:**
- Coefficient estimates become highly sensitive to small changes in data (unstable, can even flip sign).
- Standard errors of coefficients inflate → t-statistics shrink → p-values increase, making genuinely important variables look statistically insignificant.
- Hard to interpret individual coefficients ("holding all else constant" breaks down when predictors move together).
- The overall model fit ($R^2$, predictions) is usually **not** affected — it's the individual coefficient interpretation/inference that suffers.

**Detection: Variance Inflation Factor (VIF)**

For each predictor $X_j$, regress it on *all other predictors* to get $R_j^2$, then:

$$
\text{VIF}_j = \frac{1}{1 - R_j^2}
$$

- $R_j^2$ close to 1 (i.e., $X_j$ is well explained by the other predictors) → VIF blows up.
- **Interpretation guide:**
  - VIF = 1: no correlation with other predictors.
  - VIF between 1–5: moderate correlation, generally acceptable.
  - VIF > 5 (some use >10): high multicollinearity — investigate/address.

**Remedies:**
- Remove one of the highly correlated variables.
- Combine correlated variables (e.g., via PCA, or a composite index).
- Use regularization (**Ridge Regression** handles multicollinearity gracefully — see Section 6.1).
- Collect more data (sometimes reduces variance of estimates).

### 5.2 Tolerance

**Tolerance** is simply the reciprocal of VIF:

$$
\text{Tolerance}_j = 1 - R_j^2 = \frac{1}{\text{VIF}_j}
$$

It represents the proportion of variance in $X_j$ that is **not** explained by the other predictors (i.e., the "unique" information $X_j$ contributes).
- **Low tolerance (close to 0)** → high multicollinearity (most of $X_j$'s variance is explained by other predictors).
- **High tolerance (close to 1)** → low multicollinearity.
- Common rule of thumb: Tolerance < 0.1 (equivalent to VIF > 10) signals a serious multicollinearity problem.

### 5.3 Feature Scaling

**Why scale features?**
1. **Gradient descent convergence:** When features are on very different scales (e.g., "age" 0-100 vs "income" 0-10,000,000), the cost function's contour plot becomes a highly elongated ellipse, causing gradient descent to zig-zag and converge slowly. Scaling makes contours more circular, speeding convergence.
2. **Regularization fairness:** Ridge/Lasso penalize coefficient *magnitudes*. If features are on different scales, their coefficients are naturally on different scales too, so the penalty would unfairly shrink coefficients of large-scale features more/less than intended. **Scaling is essentially mandatory before regularization.**
3. **Distance-based components / interpretability:** Not strictly needed for plain OLS point estimates (OLS is scale-equivariant — predictions are identical either way), but essential for comparing the *relative importance* of coefficients, and for algorithms like gradient descent, KNN, SVM, PCA which are distance/scale sensitive.

**Common techniques:**

**a) Standardization (Z-score normalization):**

$$
x' = \frac{x - \mu}{\sigma}
$$

Centers data to mean 0, standard deviation 1. Doesn't bound values to a fixed range. Preferred when data may have outliers or when using algorithms assuming roughly Gaussian-like inputs (also the standard choice before Ridge/Lasso).

**b) Min-Max Scaling (Normalization):**

$$
x' = \frac{x - x_{min}}{x_{max} - x_{min}}
$$

Bounds values to $[0, 1]$. Sensitive to outliers (a single extreme value compresses the rest of the range). Useful when you need bounded inputs (e.g., neural network inputs, image pixel values).

**Important practical note:** Always fit the scaler (compute mean/std or min/max) on the **training set only**, then apply the same transformation to the validation/test set — fitting on the full dataset causes data leakage.

## 6. Advanced Regression Techniques

Plain OLS can overfit when there are many predictors, multicollinearity, or $p > n$ (more features than observations). **Regularization** adds a penalty term to the cost function to shrink coefficients, trading a bit of bias for a large reduction in variance (bias-variance tradeoff).

### 6.1 Ridge Regression (L2 Regularization)

**Objective function:**

$$
J(\beta) = \sum_{i=1}^n (y_i - x_i^T\beta)^2 + \lambda \sum_{j=1}^p \beta_j^2
$$

(Note: the intercept $\beta_0$ is typically **not** penalized.)

**Closed-form solution:**

$$
\hat\beta_{ridge} = (X^TX + \lambda I)^{-1}X^Ty
$$

- $\lambda$ (also called the tuning/regularization parameter, sometimes $\alpha$) controls penalty strength: $\lambda=0$ recovers OLS; $\lambda \to \infty$ shrinks all coefficients toward (but not exactly to) zero.
- Adding $\lambda I$ also makes $X^TX + \lambda I$ **always invertible**, even when $X^TX$ is singular/near-singular due to multicollinearity — this is why **Ridge is a natural remedy for multicollinearity**.
- Coefficients shrink smoothly and proportionally but **never become exactly zero** — Ridge keeps all features in the model, just with reduced magnitude.
- **Use case:** many correlated predictors, want to retain all features but stabilize estimates, or when you believe most predictors contribute a little.

### 6.2 Lasso Regression (L1 Regularization)

**Objective function:**

$$
J(\beta) = \sum_{i=1}^n (y_i - x_i^T\beta)^2 + \lambda \sum_{j=1}^p |\beta_j|
$$

- The L1 penalty's geometry (a diamond-shaped constraint region in coefficient space, vs Ridge's circular/spherical region) means the optimal solution often lands exactly on a corner of the constraint region, where one or more coefficients are **exactly zero**.
- This gives Lasso a built-in **automatic feature selection** property — it produces sparse models.
- No closed-form solution in general (the L1 penalty isn't differentiable at 0); solved via methods like **coordinate descent** or **subgradient methods** (see the from-scratch soft-thresholding implementation used to generate the plot below).
- **Use case:** many predictors, suspect only a subset are truly relevant, and want automatic variable selection alongside prediction.
- **Limitation:** with groups of highly correlated predictors, Lasso tends to arbitrarily pick just one from the group and zero out the rest, which can be unstable/inconsistent across resamples.

### 6.3 Elastic Net

**Objective function** — a weighted combination of L1 and L2 penalties:

$$
J(\beta) = \sum_{i=1}^n (y_i - x_i^T\beta)^2 + \lambda\left[\alpha\sum_{j=1}^p|\beta_j| + (1-\alpha)\sum_{j=1}^p\beta_j^2\right]
$$

- $\alpha \in [0,1]$ controls the mix: $\alpha=1$ → pure Lasso; $\alpha=0$ → pure Ridge.
- **Best of both worlds:** performs feature selection (like Lasso) while also handling groups of correlated features more gracefully (like Ridge, which tends to shrink correlated coefficients together rather than arbitrarily picking one).
- **Use case:** high-dimensional data with many correlated features (e.g., genomics, text features) — the go-to default when you're unsure whether Ridge or Lasso alone is better suited.

**Quick comparison table:**

| Property | Ridge (L2) | Lasso (L1) | Elastic Net |
|---|---|---|---|
| Penalty | $\sum \beta_j^2$ | $\sum \lvert\beta_j\rvert$ | Mix of both |
| Coefficients can be exactly 0? | No | Yes | Yes |
| Feature selection? | No | Yes | Yes |
| Handles correlated features | Shrinks together | Picks one arbitrarily | Shrinks group together |
| Closed-form solution? | Yes | No (iterative) | No (iterative) |
| Best when | Many small/medium effects, multicollinearity | Few truly relevant features | High-dim + correlated groups |

## 7. Python Implementation from Scratch

Below is a full implementation of Linear Regression using **only NumPy**.

```python
import numpy as np


# ---------------------------------------
# Train Simple Linear Regression Model
# ---------------------------------------
def train_linear_regression(X, y):

    # Calculate the mean of X and y
    x_mean = np.mean(X)
    y_mean = np.mean(y)

    # ----------------------------------------------------------
    # Numerator:
    # Measures how X and y vary together (Covariance)
    # Sum of cross deviations of x and y
    # Formula:
    # Σ[(Xi - X̄) * (Yi - Ȳ)]
    # ----------------------------------------------------------
    numerator = np.sum((X - x_mean) * (y - y_mean))

    # ----------------------------------------------------------
    # Denominator:
    # Measures the spread (variance) of X
    # Sum of squared deviations of x
    # Formula:
    # Σ[(Xi - X̄)²]
    # ----------------------------------------------------------
    denominator = np.sum((X - x_mean) ** 2)

    # ----------------------------------------------------------
    # Slope (m)
    #
    # Formula:
    # m = Covariance(X, Y) / Variance(X)
    # ----------------------------------------------------------
    slope = numerator / denominator

    # ----------------------------------------------------------
    # Intercept (b)
    #
    # Formula:
    # b = Ȳ - mX̄
    # ----------------------------------------------------------
    intercept = y_mean - slope * x_mean

    return slope, intercept


# ---------------------------------------
# Predict values using the trained model
# ---------------------------------------
def predict(X, slope, intercept):

    # Equation of a line:
    # y = mx + b
    return slope * X + intercept


# ---------------------------------------
# Mean Squared Error (MSE)
# ---------------------------------------
def mean_squared_error(y_true, y_pred):

    # Average of squared errors
    return np.mean((y_true - y_pred) ** 2)


# ---------------------------------------
# R² Score
# ---------------------------------------
def r2_score(y_true, y_pred):

    # Total variation in actual values
    ss_total = np.sum((y_true - np.mean(y_true)) ** 2)

    # Variation that our model couldn't explain
    ss_residual = np.sum((y_true - y_pred) ** 2)

    # R² = 1 - (Unexplained Variation / Total Variation)
    return 1 - (ss_residual / ss_total)


# ---------------------------------------
# Main Program
# ---------------------------------------

# Training data
X = np.array([1, 2, 3, 4, 5])
y = np.array([2, 4, 5, 4, 5])

# Train the model
slope, intercept = train_linear_regression(X, y)

# Predict output
y_pred = predict(X, slope, intercept)

# Display results
print(f"Slope (m): {slope:.2f}")
print(f"Intercept (b): {intercept:.2f}")
print("Predicted values:", y_pred)

# Model evaluation
print(f"Mean Squared Error: {mean_squared_error(y, y_pred):.2f}")
print(f"R² Score: {r2_score(y, y_pred):.2f}")
```
## 8. Common Interview Questions & Answers

**Q1: What is the difference between R² and Adjusted R²?**
> R² always increases (or stays the same) as you add more predictors, even irrelevant ones, because it can never worsen the fit on training data. Adjusted R² adds a penalty for the number of predictors relative to sample size, so it can actually decrease if a new variable doesn't improve the model enough to justify its inclusion. Adjusted R² is a fairer metric when comparing models with different numbers of features.

**Q2: Why is OLS called "Ordinary Least Squares"? What does it minimize?**
> OLS minimizes the residual sum of squares (RSS) — the sum of squared vertical distances between observed and predicted y-values. "Ordinary" distinguishes it from variants like Weighted or Generalized Least Squares, which modify the objective to account for heteroscedasticity or correlated errors.

**Q3: What happens if you don't scale features before Ridge/Lasso?**
> Since the penalty term sums coefficient magnitudes (or squares), features on a larger raw scale will naturally get smaller coefficients (and vice versa) purely due to units — not because they're less important. Without scaling, the penalty is applied unevenly across features, distorting which variables get shrunk or zeroed out. Standardizing features first ensures the penalty treats each feature fairly.

**Q4: Explain the bias-variance tradeoff in the context of Ridge/Lasso.**
> Plain OLS is unbiased but can have high variance when there's multicollinearity or many features relative to observations — small changes in training data cause large swings in coefficients. Ridge/Lasso intentionally introduce a small amount of bias (by shrinking coefficients) in exchange for a substantial reduction in variance, which usually improves generalization (test-set performance) even though it worsens training-set fit slightly.

**Q5: How would you detect and handle multicollinearity?**
> Detect via a correlation matrix (for pairwise relationships) and VIF (for multi-way relationships that pairwise correlation might miss). To address it: remove/combine redundant features, apply PCA to create uncorrelated components, or use Ridge Regression, which handles correlated predictors natively by stabilizing the matrix inversion.

**Q6: Why might a model have a high R² but still be a poor model?**
> High R² only reflects how much variance in y is explained *on the training/fitting data* — it says nothing about whether assumptions are violated (e.g., non-linearity, heteroscedasticity), whether the model generalizes to new data (could be overfit, especially with many predictors), or whether coefficients are individually meaningful/significant. A model can have high R² and still produce misleading inferences or poor out-of-sample predictions.

**Q7: What's the difference between Type I and Type II error in the context of hypothesis testing on coefficients?**
> Type I error is rejecting $H_0$ (concluding a predictor matters) when it actually doesn't — a false positive, controlled by the significance level α (e.g., 0.05). Type II error is failing to reject $H_0$ (concluding a predictor doesn't matter) when it actually does — a false negative, related to the statistical power of the test. Larger sample sizes generally reduce Type II error for a fixed Type I error rate.

**Q8: Why does Lasso produce sparse solutions but Ridge does not?**
> Geometrically, the L1 penalty's constraint region is a diamond (in 2D) with sharp corners on the coordinate axes; the L2 penalty's constraint region is a smooth circle/sphere. When you find where the elliptical RSS contours first touch the constraint region, the diamond's corners make it much more likely that the touching point lies exactly on an axis (i.e., some coefficient = 0). The circle has no corners, so the touching point is generically not on an axis — coefficients shrink but rarely hit exactly zero.

**Q9: What is heteroscedasticity, and why does it matter even if it doesn't bias coefficients?**
> Heteroscedasticity means the variance of the residuals is not constant across the range of fitted values or predictors. Even though OLS coefficients remain unbiased under heteroscedasticity, the standard errors computed by standard OLS formulas become invalid, which corrupts p-values, t-statistics, and confidence intervals — so your inferences about which variables matter can be wrong even if predictions are fine.

**Q10: How do you interpret a coefficient in multiple linear regression?**
> $\beta_j$ represents the expected change in $y$ for a one-unit increase in $x_j$, **holding all other predictors constant**. This "holding constant" interpretation breaks down under multicollinearity, since in practice correlated predictors rarely move independently of each other.

**Q11: What's the difference between Cook's Distance and leverage?**
> Leverage ($h_{ii}$) only measures how unusual a point's predictor (X) values are — it reflects *potential* to influence the fit. Cook's Distance combines leverage with the size of the residual, measuring *actual* influence on the fitted coefficients. A point can have high leverage but low Cook's Distance if its y-value still fits the overall trend well.

**Q12: When would you prefer Gradient Descent over the Normal Equation (and vice versa)?**
> The Normal Equation is exact and requires no hyperparameter tuning, but involves inverting/solving a $(p+1)\times(p+1)$ matrix, which costs roughly $O(p^3)$ — impractical when $p$ (number of features) is very large. Gradient Descent scales much better to high-dimensional data and huge datasets (especially with mini-batch/stochastic variants) but requires tuning the learning rate and iterating until convergence, and may only reach an approximate solution.

**Q13: Can Linear Regression be used for classification?**
> Technically you can fit it to a 0/1 target, but it's a poor choice: predictions aren't bounded to [0,1] (so they can't be interpreted as probabilities), it's sensitive to outliers, and it assumes constant error variance, which is violated for binary outcomes. Logistic Regression, which uses a sigmoid link function and a log-loss objective, is the appropriate alternative.

**Q14: What is the difference between correlation and regression coefficients?**
> Correlation ($r$) is symmetric, unitless (between -1 and 1), and just measures the strength/direction of a *linear association* between two variables with no implied direction of causality or prediction. A regression coefficient ($\beta$) is directional (predicting y from x), has units (y-units per x-unit), and can change depending on what other variables are included in the model — correlation between two variables alone does not.
