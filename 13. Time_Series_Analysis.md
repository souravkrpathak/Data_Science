# Time Series Analysis

---

## 1. Definition and Fundamental Concepts

**Time Series** = a sequence of data points collected/recorded at successive, equally spaced points in time (hourly, daily, monthly, yearly).

Examples: daily stock prices, monthly call center volume, hourly temperature, EY call volume data (SARIMAX use case), quarterly GDP.

### Why Time Series is different from normal regression data
| Normal Regression | Time Series |
|---|---|
| Rows are independent (i.i.d.) | Rows (time steps) are dependent on previous rows |
| Order of rows doesn't matter | Order matters — shuffling destroys the signal |
| No concept of "past influencing future" | Past values directly influence future values (autocorrelation) |

### Core assumption
The value at time `t` depends on values before `t` (`t-1`, `t-2`, ...). This dependency is what we try to model.

### Two broad goals
1. **Time Series Analysis** — understand structure (trend, seasonality, what's driving it).
2. **Time Series Forecasting** — predict future values using the understood structure.

---

## 2. Important Terms

A time series is generally thought of as being made up of 4 components:

```
Observed = Trend + Seasonality + Cyclic + Residual (Additive)
Observed = Trend × Seasonality × Cyclic × Residual (Multiplicative)
```

### Trend
The long-term general direction of the data (upward, downward, flat), ignoring short-term fluctuations.
- Example: overall increasing usage of internet over 10 years.

### Seasonality
A **pattern that repeats at a fixed, known frequency** (daily, weekly, monthly, yearly) due to calendar-related reasons.
- Example: ice cream sales spike every summer, retail sales spike every December.
- Key property: **fixed and known period**.

### Cycle
A pattern that repeats but **without a fixed period** — driven by economic or business conditions, not the calendar.
- Example: business cycles (boom-recession-boom), typically lasting several years, length is not fixed.
- **Trick distinction (common interview trap):** Seasonality has a *fixed, known* period (always 12 months, always 7 days). A Cycle has a *variable, unknown* period — could be 3 years this time, 7 years next time.

### Residual (a.k.a. Noise / Irregular component)
Whatever is **left over** after removing Trend, Seasonality, and Cycle. Ideally, residuals should look like **random white noise** — no pattern left in them. If residuals still have a pattern, your model hasn't captured everything.

### Additive vs Multiplicative decomposition
- **Additive**: use when seasonal fluctuations are roughly **constant in magnitude** regardless of the trend level. `Y = T + S + R`
- **Multiplicative**: use when seasonal fluctuations **grow/shrink proportionally** with the trend level. `Y = T × S × R`
- Simple check: plot the data. If the "spread" of seasonal swings grows as the series grows → multiplicative.

---

## 3. Stationarity

### What is a Stationary series?
A series whose **statistical properties** (mean, variance, autocorrelation) **do not change over time**.

Formally (weak/covariance stationarity):
1. Mean is constant over time
2. Variance is constant over time
3. Covariance between `Y_t` and `Y_{t+k}` depends only on the lag `k`, not on actual time `t`

### Why do we need stationary data?
1. **Most classical models (AR, MA, ARIMA) assume stationarity.** The math behind them (constant coefficients estimated from the whole series) only makes sense if the underlying statistical behavior isn't shifting.
2. A **non-stationary series is unpredictable in a structured way** — if the mean itself is drifting, "average behavior" learned from the past doesn't apply to the future.
3. Spurious correlations: two non-stationary trending series can look highly correlated purely because both are trending, not because they're related. Stationarity avoids this trap.
4. It lets us build models with a **fixed, finite set of parameters** that don't need to change with time.

### How to convert non-stationary → stationary
| Technique | When to use | How |
|---|---|---|
| **Differencing** | Trend present | `Y'_t = Y_t - Y_{t-1}` (first-order). Repeat for 2nd order if needed |
| **Seasonal differencing** | Seasonality present | `Y'_t = Y_t - Y_{t-m}` where `m` = season length (e.g., 12 for monthly) |
| **Log transform** | Variance increases with level (multiplicative-type growth) | `log(Y_t)` — stabilizes variance |
| **Box-Cox transform** | General variance stabilization | Generalized version of log transform |
| **Detrending (regression)** | Deterministic trend | Fit trend line, subtract it |
| **Square root / power transform** | Mild variance issues | `sqrt(Y_t)` |

**Rule of thumb order:** first stabilize variance (log/Box-Cox) → then remove trend (differencing) → then remove seasonality (seasonal differencing).

## 4. Stationarity Check

### 1. Visual check
Plot the series. Look for obvious trend, changing variance, or seasonal pattern. Quick but subjective.

### 2. Rolling statistics
Plot rolling mean and rolling standard deviation (e.g., 12-month window). If they are roughly flat lines → likely stationary. If they trend up/down → non-stationary.

### 3. ADF Test (Augmented Dickey-Fuller) — most commonly asked in interviews
- **Null Hypothesis (H0):** series is **non-stationary** (has a unit root)
- **Alternate Hypothesis (H1):** series is **stationary**
- Decision rule: if **p-value < 0.05** → reject H0 → series **is stationary**.
- If p-value > 0.05 → fail to reject H0 → series is **non-stationary**, needs differencing.

```python
from statsmodels.tsa.stattools import adfuller
result = adfuller(series)
print('ADF Statistic:', result[0])
print('p-value:', result[1])
```

### 4. KPSS Test (Kwiatkowski-Phillips-Schmidt-Shin)
- **Null Hypothesis (H0):** series **is stationary**
- **Alternate Hypothesis (H1):** series is **non-stationary**
- This is the **opposite direction** of ADF — a classic interview trick question.
- If p-value < 0.05 → reject H0 → series is **non-stationary**.

**Best practice:** Use ADF and KPSS **together**.
| ADF | KPSS | Conclusion |
|---|---|---|
| Stationary | Stationary | Series is stationary ✅ |
| Non-stationary | Non-stationary | Series is non-stationary, needs differencing |
| Stationary | Non-stationary | Trend-stationary → needs detrending |
| Non-stationary | Stationary | Difference-stationary → needs differencing |

## 5. Smoothing Techniques

### Simple Moving Average (SMA)
Average of the last `n` observations, window slides forward.
```
SMA_t = (Y_t + Y_{t-1} + ... + Y_{t-n+1}) / n
```
- Simple, smooths noise, but **lags behind** sudden changes and gives **equal weight** to all points in the window (even the oldest).
- Used for basic trend visualization, not great for forecasting alone.

### Cumulative Moving Average (CMA)
Average of **all data points up to time t** (expanding window, not fixed size).
```
CMA_t = (Y_1 + Y_2 + ... + Y_t) / t
```
- Every new point has progressively less influence as `t` grows (since it's diluted across more history).
- Rarely used for forecasting; more for understanding overall running average.

### Exponential Moving Average (EMA)
Gives **more weight to recent observations**, weights decay exponentially for older data.
```
EMA_t = α·Y_t + (1-α)·EMA_{t-1}
```
- `α` (smoothing factor, 0 < α < 1): higher α → more weight to recent data → more reactive/less smooth. Lower α → smoother but slower to react.
- Fixes SMA's biggest weakness: reacts faster to recent changes, doesn't need to store the whole window.

### Holt-Winters Method (Triple Exponential Smoothing)
Extends EMA to handle **Trend** and **Seasonality**, not just level. Has 3 smoothing equations:

1. **Level** (α): `L_t = α(Y_t / S_{t-m}) + (1-α)(L_{t-1} + T_{t-1})`
2. **Trend** (β): `T_t = β(L_t - L_{t-1}) + (1-β)T_{t-1}`
3. **Seasonality** (γ): `S_t = γ(Y_t / L_t) + (1-γ)S_{t-m}`

Where `m` = season length.

- **Simple Exponential Smoothing (SES)**: no trend, no seasonality — flat forecast.
- **Holt's Linear Trend method (Double Exponential Smoothing)**: handles level + trend, no seasonality.
- **Holt-Winters (Triple Exponential Smoothing)**: handles level + trend + seasonality.
- Two variants: **Additive** (seasonal swings constant) and **Multiplicative** (seasonal swings scale with level).

```python
from statsmodels.tsa.holtwinters import ExponentialSmoothing
model = ExponentialSmoothing(series, trend='add', seasonal='add', seasonal_periods=12).fit()
forecast = model.forecast(12)
```

## 6. ACF and PACF

These are the two most important diagnostic plots for identifying AR/MA order.

### ACF — Autocorrelation Function
Measures correlation between `Y_t` and `Y_{t-k}`, **including all the indirect paths** through intermediate lags (`t-1, t-2, ..., t-k+1`).
- Helps identify the **MA(q)** order: for a pure MA(q) process, ACF **cuts off sharply after lag q**.

### PACF — Partial Autocorrelation Function
Measures correlation between `Y_t` and `Y_{t-k}` **after removing the effect of the intermediate lags** (the "pure" direct correlation at lag k).
- Helps identify the **AR(p)** order: for a pure AR(p) process, PACF **cuts off sharply after lag p**.

### Quick identification table
| Process | ACF | PACF |
|---|---|---|
| AR(p) | Tails off (decays gradually) | Cuts off after lag p |
| MA(q) | Cuts off after lag q | Tails off (decays gradually) |
| ARMA(p,q) | Tails off | Tails off |

```python
from statsmodels.graphics.tsaplots import plot_acf, plot_pacf
plot_acf(series, lags=40)
plot_pacf(series, lags=40)
```

**Interview trap:** People confuse which plot identifies which parameter. Memory trick: **P**ACF → **P**(AR term). ACF (no P) → MA term (indirectly, the "full" correlation matches MA's structure).

## 7. ARIMA, SARIMA, ARIMAX, SARIMAX

### AR — AutoRegressive
Current value depends on its own **past values**.
```
Y_t = c + φ1·Y_{t-1} + φ2·Y_{t-2} + ... + φp·Y_{t-p} + ε_t
```
Order = `p`

### MA — Moving Average
Current value depends on **past forecast errors** (not past values!).
```
Y_t = c + ε_t + θ1·ε_{t-1} + ... + θq·ε_{t-q}
```
Order = `q`
**Common confusion:** MA here is NOT the same as the "Moving Average" smoothing technique from Section 5. It models past *error terms*, not past raw values.

### I — Integrated
The number of times you need to **difference** the series to make it stationary. Order = `d`.

### ARIMA(p, d, q)
Combines all three: AutoRegressive + Integrated (differencing) + Moving Average.
- Works on **non-seasonal** stationary (after differencing) data.

### SARIMA(p,d,q)(P,D,Q,m)
ARIMA + explicit **seasonal** components.
- `(p,d,q)` → non-seasonal part
- `(P,D,Q,m)` → seasonal part: seasonal AR order, seasonal differencing order, seasonal MA order, and `m` = length of season (12 for monthly, 7 for weekly-daily data, 4 for quarterly)
- Use when data has **clear repeating seasonality** (e.g., call center monthly volume, retail sales).

### ARIMAX
ARIMA + **eXogenous variables** (external predictors).
- Example: forecasting sales using ARIMA, but also feeding in "marketing spend" or "holiday flag" as an external regressor.
- `Y_t = ARIMA(p,d,q) terms + β·X_t + ε_t`

### SARIMAX
SARIMA + Exogenous variables — the most general and commonly used in production (e.g., call volume forecasting with holiday flags, promo flags as exogenous regressors).

```python
from statsmodels.tsa.statespace.sarimax import SARIMAX
model = SARIMAX(y_train, exog=exog_train,
                 order=(p,d,q),
                 seasonal_order=(P,D,Q,m)).fit()
forecast = model.forecast(steps=12, exog=exog_test)
```

## 8. Determining p, d, q (non-seasonal)

### d — order of differencing
- Run ADF/KPSS test on raw series.
- If non-stationary → difference once, test again.
- Repeat until stationary. **In practice d is rarely more than 1 or 2** (over-differencing adds noise and hurts the model).

### p — AR order
- Look at **PACF plot** on the (differenced, stationary) series.
- `p` = the lag **after which PACF cuts off / becomes insignificant** (inside the confidence band).

### q — MA order
- Look at **ACF plot** on the (differenced, stationary) series.
- `q` = the lag **after which ACF cuts off / becomes insignificant**.

### Practical approach (used in real projects)
1. Manual ACF/PACF reading gives a **starting range**.
2. **Grid search** over small ranges of p, d, q (e.g., 0–3 each).
3. Select the combination with the **lowest AIC / BIC** (information criteria — penalize model complexity, prevent overfitting).
4. **Auto-ARIMA** (`pmdarima` library) automates this grid search.

```python
import pmdarima as pm
model = pm.auto_arima(series, seasonal=False, trace=True,
                       stepwise=True, information_criterion='aic')
print(model.order)  # (p,d,q)
```

## 9. Determining Seasonal P, D, Q, m

### m — season length
- Determined by domain knowledge / data frequency: 12 (monthly data, yearly seasonality), 7 (daily data, weekly seasonality), 4 (quarterly data, yearly seasonality).
- Can also confirm via a strong spike in ACF at lag `m`.

### D — seasonal differencing order
- Apply seasonal differencing: `Y_t - Y_{t-m}`.
- Check stationarity again (ADF/KPSS) and check if the seasonal spike in ACF at lag `m` has disappeared.
- Usually **D = 0 or 1** — rarely more, as over-differencing seasonally destroys signal.

### P — seasonal AR order
- Look at PACF at **seasonal lags** (`m, 2m, 3m...`) after seasonal differencing.
- Significant spike at lag `m` only → P=1. Spikes at `m` and `2m` → P=2, etc.

### Q — seasonal MA order
- Look at ACF at **seasonal lags** (`m, 2m, ...`) after seasonal differencing, same logic as above.

### Practical approach
Same as before — use `auto_arima` with `seasonal=True` and `m` specified; it grid-searches both non-seasonal and seasonal orders using AIC/BIC.

```python
model = pm.auto_arima(series, seasonal=True, m=12, trace=True,
                       stepwise=True, information_criterion='aic')
print(model.order, model.seasonal_order)
```

## 10. Time Series Prediction using LSTM

### Why LSTM for time series?
- LSTM (Long Short-Term Memory) is a type of RNN designed to **remember long-range dependencies** using gates (forget, input, output) and a cell state — solves the vanishing gradient problem plain RNNs have.
- Unlike ARIMA (linear, assumes stationarity), LSTM can capture **non-linear patterns** and doesn't strictly require stationary input, though scaling still helps a lot.
- Good when you have **large amounts of data** and complex, non-linear relationships (e.g., multivariate series, long sequences). For smaller/simpler seasonal series, SARIMA often still wins and is more interpretable.

### Steps to build an LSTM time series model
1. **Scale the data** (MinMaxScaler, since LSTMs are sensitive to input scale — usually 0 to 1).
2. **Create supervised sequences** — convert the series into (X, y) pairs using a sliding window: use last `n` time steps to predict the next step.
3. **Reshape input** to 3D: `(samples, timesteps, features)` — required LSTM input shape.
4. **Build the network**: one or more LSTM layers, optionally Dropout for regularization, followed by a Dense output layer.
5. **Train** with an appropriate loss (MSE for regression) and optimizer (Adam).
6. **Inverse-transform** predictions back to original scale before evaluating (RMSE/MAE/MAPE).

```python
from sklearn.preprocessing import MinMaxScaler
from tensorflow.keras.models import Sequential
from tensorflow.keras.layers import LSTM, Dense, Dropout
import numpy as np

# 1. Scale
scaler = MinMaxScaler()
scaled = scaler.fit_transform(series.values.reshape(-1,1))

# 2. Create sequences
def create_sequences(data, window):
    X, y = [], []
    for i in range(len(data) - window):
        X.append(data[i:i+window])
        y.append(data[i+window])
    return np.array(X), np.array(y)

window = 12
X, y = create_sequences(scaled, window)
X = X.reshape((X.shape[0], X.shape[1], 1))  # (samples, timesteps, features)

# 3. Build model
model = Sequential([
    LSTM(50, activation='relu', input_shape=(window, 1)),
    Dropout(0.2),
    Dense(1)
])
model.compile(optimizer='adam', loss='mse')
model.fit(X, y, epochs=20, batch_size=16, verbose=0)
```

### Key practical notes
- **Train/test split must be chronological** — never shuffle time series data.
- Window size (`lookback`) is a key hyperparameter, similar in spirit to choosing `p` in AR models.
- For multivariate forecasting (multiple exogenous features), just add more feature columns before reshaping.
- **Bidirectional LSTM / GRU / Attention / Transformer-based (e.g., Temporal Fusion Transformer)** models are newer alternatives worth mentioning as extensions in senior-level interviews.

## 11. Other Important Concepts

### Train-Test split for Time Series
- **Never** randomly shuffle and split. Always split chronologically: train on earlier period, test on later period.
- Use **walk-forward validation / expanding window cross-validation** (`TimeSeriesSplit` in sklearn) instead of k-fold CV.

### Evaluation Metrics
| Metric | Formula concept | Notes |
|---|---|---|
| MAE | mean(|actual - predicted|) | Same unit as data, easy to interpret |
| MSE / RMSE | mean(error²) / sqrt(MSE) | Penalizes large errors more |
| MAPE | mean(|error/actual|) × 100 | Percentage, scale-independent, but breaks when actual = 0 |
| SMAPE | symmetric MAPE | Fixes some MAPE issues, bounded |
| AIC / BIC | penalized likelihood | For comparing model complexity, not accuracy on test data |

### White Noise
A series with constant mean (usually 0), constant variance, and **zero autocorrelation** at all lags. If your model's residuals are white noise → model has captured all the structure, nothing left to learn.

### Random Walk
`Y_t = Y_{t-1} + ε_t` — a special non-stationary case where the best prediction of tomorrow is simply today's value. Many financial series (like stock prices) behave close to a random walk, which is why they're notoriously hard to forecast.

### Ljung-Box Test
Statistical test to check if **residuals are white noise** (no leftover autocorrelation). Used after fitting ARIMA/SARIMA to validate the model. H0 = residuals are independently distributed (good fit).

### Heteroscedasticity in time series
When variance of residuals changes over time (e.g., volatility clustering in stock returns). Models like **GARCH** are specifically built for this (used alongside ARIMA — ARIMA models the mean, GARCH models the variance).

### Multivariate Time Series
When you forecast one series using multiple related series together.
- **VAR (Vector AutoRegression)**: all variables are treated symmetrically, each modeled as a function of past values of itself AND other variables. Requires all series stationary.
- **VARMAX**: VAR + moving average + exogenous variables.

### Prophet (Facebook/Meta's library)
An alternative to ARIMA family — decomposes series into trend + seasonality + holiday effects using an additive model, robust to missing data and outliers, easier to tune than SARIMA for business use cases with strong seasonality/holidays.

### Drift Detection (relevant to production ML systems)
In production forecasting systems, monitor if the statistical properties of incoming data are drifting from training data (concept drift / data drift) — important because time series models trained on old patterns silently degrade as real-world patterns shift.

### Lag Features & Rolling Features (for ML-based forecasting, e.g., XGBoost/LightGBM on time series)
Instead of pure statistical models, many production systems convert time series into a **tabular supervised learning problem**:
- Lag features: `Y_{t-1}, Y_{t-2}, ..., Y_{t-7}`
- Rolling statistics: rolling mean/std over past 7/30 days
- Date-based features: day of week, month, is_holiday
- Then feed into any regression model (XGBoost, Random Forest, etc.)
- Very common in industry because it lets you use powerful gradient boosting models plus easily add exogenous features.

### Diebold-Mariano Test
Statistical test to compare forecast accuracy between two competing models — useful when justifying "Model A is significantly better than Model B" beyond just eyeballing RMSE.

## 12. Simple, Illustrative Code Example (End-to-End)

A minimal but complete SARIMAX pipeline on a monthly seasonal series:

```python
import pandas as pd
import numpy as np
import matplotlib.pyplot as plt
from statsmodels.tsa.stattools import adfuller
from statsmodels.tsa.statespace.sarimax import SARIMAX
from sklearn.metrics import mean_absolute_percentage_error

# ---- 1. Load data ----
# Assume df has a DateTime index and a 'value' column (e.g., monthly call volume)
df = pd.read_csv('monthly_data.csv', parse_dates=['date'], index_col='date')
series = df['value']

# ---- 2. Check stationarity ----
result = adfuller(series)
print(f"ADF p-value: {result[1]:.4f}")
d = 0 if result[1] < 0.05 else 1   # simple decision rule

# ---- 3. Train-test split (chronological) ----
train = series[:-12]
test = series[-12:]

# ---- 4. Fit SARIMAX ----
model = SARIMAX(train,
                 order=(1, d, 1),
                 seasonal_order=(1, 1, 1, 12),
                 enforce_stationarity=False,
                 enforce_invertibility=False)
fitted = model.fit(disp=False)
print(fitted.summary())

# ---- 5. Forecast ----
forecast = fitted.forecast(steps=12)

# ---- 6. Evaluate ----
mape = mean_absolute_percentage_error(test, forecast) * 100
print(f"Test MAPE: {mape:.2f}%")

# ---- 7. Plot ----
plt.figure(figsize=(10,5))
plt.plot(train.index, train, label='Train')
plt.plot(test.index, test, label='Actual')
plt.plot(test.index, forecast, label='Forecast', linestyle='--')
plt.legend()
plt.title('SARIMAX Forecast vs Actual')
plt.show()

# ---- 8. Residual diagnostics ----
from statsmodels.stats.diagnostic import acorr_ljungbox
residuals = fitted.resid
lb_test = acorr_ljungbox(residuals, lags=[10], return_df=True)
print(lb_test)  # p-value > 0.05 → residuals are white noise → good fit
```

## 13. Common & Tricky Interview Questions with Expert Answers

**Q1. Why can't we directly apply linear regression to time series data?**
> Linear regression assumes independent, identically distributed (i.i.d.) errors with no autocorrelation. Time series data violates this — consecutive observations are correlated, so regression's standard errors and significance tests become unreliable (and it ignores the temporal ordering/dependency entirely, which is exactly the signal we want to exploit).

**Q2. What's the difference between Seasonality and Cyclicity?**
> Seasonality has a fixed, known, calendar-based period (always every 12 months, every 7 days). Cyclicity has no fixed period — it's driven by broader economic or business conditions and can vary in length each time (e.g., 3 years one cycle, 7 years the next).

**Q3. Why does ADF test's null hypothesis say "non-stationary" while KPSS says "stationary"? Isn't that confusing?**
> Yes, and it's intentionally tested this way to cross-validate. ADF is designed to detect a unit root (non-stationarity) as the default assumption, requiring evidence to reject it. KPSS flips it — assumes stationarity as default. Using both avoids over-relying on a single test's Type I/II error tendencies; when both agree, we're much more confident.

**Q4. If differencing once doesn't make the series stationary, should I keep differencing many times?**
> No — over-differencing is a real risk. Each differencing operation removes structure but also injects noise and can introduce artificial negative autocorrelation. In practice, d rarely exceeds 2 for non-seasonal data and D rarely exceeds 1 for seasonal data. If differencing twice doesn't help, the problem is likely elsewhere (wrong transform, structural break, needs seasonal differencing instead).

**Q5. How do you choose between ARIMA and LSTM for a forecasting problem?**
> It depends on data size, pattern complexity, and interpretability needs. ARIMA/SARIMA works well with limited data, clear linear/seasonal patterns, and needs to be explainable (important in regulated environments like banking — coefficients are interpretable). LSTM shines with large datasets, multiple correlated variables, non-linear relationships, and long historical context, but needs more data, is harder to interpret, and is more expensive to tune. In practice, I'd start with a simple SARIMA baseline, then justify the added complexity of LSTM only if it meaningfully beats that baseline on held-out data.

**Q6. What happens if you don't difference a non-stationary series and just run ARIMA anyway?**
> The model's parameter estimates become unreliable, forecasts tend to just extrapolate the trend blindly (often diverging), and confidence intervals are invalid because the constant-mean/variance assumption behind the underlying math is violated.

**Q7. In ACF/PACF, why does an AR(p) process show a gradual decay in ACF but a sharp cutoff in PACF?**
> Because ACF measures total correlation between Y_t and Y_{t-k}, including indirect correlation propagated through intermediate lags — since an AR process's influence decays but never fully vanishes across lags, ACF tails off. PACF strips out that indirect chain effect and isolates the *direct* relationship at each lag — since a true AR(p) process by definition has no direct dependency beyond lag p, PACF cuts off sharply right after p.

**Q8. What's the practical difference between MA(q) in ARIMA and a moving-average smoothing technique (like SMA)?**
> They share a name but are different concepts. SMA/EMA are simple *smoothing* techniques that average past raw *values*. The MA(q) component in ARIMA models the current value as a function of past *forecast error terms* (shocks), not past raw values — it's a way of saying "if I was off by X last period, that influences my error correction this period."

**Q9. Why use log transform before differencing sometimes?**
> If the variance of the series grows as the level grows (multiplicative-type heteroscedasticity, common in financial/business growth data), differencing alone won't stabilize variance — only the mean. Log transform compresses large values proportionally more than small ones, stabilizing variance first; then differencing handles the trend in mean.

**Q10. Your SARIMAX model has great training accuracy but poor test accuracy. What could be wrong?**
> Likely overfitting from a too-complex order (high p,q or P,Q chosen purely by lowest in-sample AIC without out-of-sample validation), possible data leakage (e.g., exogenous variables that weren't actually available at forecast time), or a structural break in the test period (regime change, e.g., COVID-like shock) that the model — trained on stable historical patterns — can't anticipate. I'd check residual diagnostics on training data, re-run with a proper walk-forward validation, and inspect if the test period had any unusual real-world events.

**Q11. How do you handle missing values or irregular timestamps in a time series before modeling?**
> First check *why* they're missing (sensor failure vs. genuinely no data e.g. market holidays). For small gaps, use interpolation (linear or seasonal-aware). For structurally missing points (e.g., weekends in stock data), often better to explicitly resample to the correct frequency rather than force-fill. Avoid naive mean-imputation — it destroys the temporal structure/autocorrelation you're trying to model.

**Q12. What is the "curse" of using AIC/BIC alone to pick ARIMA order?**
> AIC/BIC are in-sample, likelihood-based metrics — a lower AIC only tells you the model fits the training data well relative to its complexity; it doesn't guarantee better out-of-sample forecast accuracy. Best practice is to use AIC/BIC as a first-pass filter to narrow candidate models, then confirm the final choice using out-of-sample validation (walk-forward / rolling-origin CV) with a forecast-accuracy metric like RMSE or MAPE.

**Q13. Explain why shuffling data before train-test split is a serious mistake in time series.**
> It causes data leakage — if future data points end up in the training set, the model implicitly "sees the future" during training (e.g., through overlapping rolling window features), leading to unrealistically good validation scores that collapse in real production use. Time series validation must always respect chronological order — the model should only ever be trained on data that would have actually been available at prediction time.

**Q14. What's the relationship between differencing order 'd' in ARIMA and the number of unit roots in the series?**
> `d` literally equals the number of unit roots that need to be removed to achieve stationarity. Each differencing operation removes exactly one unit root. If ADF still shows non-stationarity after one difference, there's likely more than one unit root, requiring `d=2` (rare in practice, and worth double-checking the data for a genuine structural issue if you find yourself needing more than that).

**Q15. Can you use ARIMA for multivariate forecasting? If not, what would you use instead?**
> Pure ARIMA is univariate. If you want a single target influenced by other time-varying predictors, use **ARIMAX/SARIMAX** (exogenous variables, but exogenous variables are treated as one-directional inputs, not modeled themselves). If you need to jointly model multiple interacting time series where each affects the others, use **VAR/VARMAX**, or a machine-learning approach like gradient boosting with lag features from all series, or a multivariate LSTM.

### Quick Revision Cheat-Sheet

- **Stationary?** → ADF (H0: non-stationary) + KPSS (H0: stationary), use both.
- **d** → from differencing needed for stationarity (ADF/KPSS).
- **p** → PACF cutoff lag.
- **q** → ACF cutoff lag.
- **Seasonal P,D,Q,m** → same logic, but at seasonal lags (m, 2m, 3m...).
- **Trend** = long-term direction. **Seasonality** = fixed-period repeat. **Cycle** = variable-period repeat. **Residual** = leftover noise.
- **SMA** = equal-weight window. **EMA** = exponentially decaying weight, more reactive. **Holt-Winters** = EMA extended for trend + seasonality.
- **ARIMA** = non-seasonal. **SARIMA** = + seasonality. **ARIMAX/SARIMAX** = + external regressors.
- **LSTM** = for non-linear, large-data, multivariate cases; needs scaling + sequence windowing + chronological split.
- Always validate with **walk-forward CV**, never random shuffle.
