# Dimensionality Reduction

---

## 1. Definition and Fundamental Concepts

**Dimensionality Reduction** is the process of reducing the number of input features (columns/variables) in a dataset, while keeping as much useful information as possible.

Think of it like this: if you have a dataset with 1,000 columns, most of that information is often repeated, correlated, or just noise. Dimensionality reduction tries to compress this into, say, 10–50 columns that still tell almost the same story.

There are two broad families:

| Type | What it does | Examples |
|---|---|---|
| **Feature Selection** | Picks a subset of the *original* features (drops the rest) | Forward selection, Backward elimination, LASSO |
| **Feature Extraction** | *Creates new* features that are combinations of the original ones | PCA, Kernel PCA, LDA, t-SNE, UMAP, Autoencoders |

This note focuses on **feature extraction** methods: PCA, Kernel PCA, and LDA — the three most commonly asked about in interviews.

### Key fundamental terms you must know

- **Dimensionality**: number of features/columns in your dataset.
- **Variance**: how spread out the data is. High variance = more information (in PCA's world).
- **Covariance Matrix**: tells you how features vary *together*. Diagonal = variance of each feature; off-diagonal = how pairs of features move together.
- **Eigenvectors & Eigenvalues**: eigenvectors give you *directions*, eigenvalues tell you how much *variance* is captured along that direction. Bigger eigenvalue = more important direction.
- **Projection**: mapping data from a high-dimensional space onto a lower-dimensional space (like casting a shadow of a 3D object onto a 2D wall).
- **Linear vs Non-linear reduction**: PCA and LDA are linear (straight-line projections). Kernel PCA, t-SNE, UMAP handle non-linear (curved) structure.

## 2. Why Do We Need Dimensionality Reduction?

Imagine you're studying for interviews and you have 500 flashcards, but 480 of them repeat the same 20 ideas in different words. You don't need all 500 — a smart summary of ~20 cards is enough. That's exactly what dimensionality reduction does to data.

### Key reasons:

1. **Curse of Dimensionality**: As the number of features grows, the data becomes very sparse in that space. Distances between points become less meaningful, which hurts algorithms like KNN, clustering, and distance-based models.

2. **Reduces Overfitting**: Fewer, more meaningful features mean the model is less likely to memorize noise.

3. **Speeds up Training**: Less data to crunch = faster model training and inference. Very important in production ML systems.

4. **Removes Multicollinearity**: When features are highly correlated (like "height in cm" and "height in inches"), regression coefficients become unstable. Dimensionality reduction can remove this redundancy.

5. **Visualization**: Humans can only see in 2D or 3D. Reducing 50 features down to 2 or 3 lets us plot and visually understand the data (clusters, outliers, patterns).

6. **Storage and Cost Efficiency**: Less data to store and process, which matters at scale (e.g., large-scale industry pipelines).

7. **Noise Reduction**: Small variance directions are often just noise. Dropping them can actually make the model more robust.

> **Interview tip**: If asked "why not just use all features and let the model figure it out?" — mention the curse of dimensionality, overfitting risk, and compute cost. Models don't automatically know which features are noise; they may end up giving noise unwarranted importance, especially with limited training data.

## 3. Principal Component Analysis (PCA)

### 3.1 Definition

**PCA** is an **unsupervised**, **linear** dimensionality reduction technique. It transforms the original correlated features into a new set of **uncorrelated** features called **Principal Components (PCs)**, ordered by how much variance (information) they capture.

- PC1 captures the most variance.
- PC2 captures the next most variance, while being **orthogonal** (perpendicular / uncorrelated) to PC1.
- And so on.

### 3.2 Core Principle

PCA's core idea: **"Find the direction along which the data varies the most, and project the data onto that direction."**

Why variance? Because directions with high variance are assumed to carry the most information. A direction where all points collapse to nearly the same value tells you almost nothing about the data — it's like a survey question everyone gave the same answer to.

Geometrically: PCA finds a *new set of axes* (a rotated coordinate system) such that when you look at the data along the first axis, you see the maximum spread. This is done using **eigenvectors of the covariance matrix**.

### 3.3 Step-by-Step Working of PCA

**Step 1: Standardize the data**
Subtract the mean and divide by standard deviation for each feature. This is critical — PCA is sensitive to scale. A feature measured in thousands (like salary) would dominate a feature measured in single digits (like age) if you don't standardize.

$$ z = \frac{x - \mu}{\sigma} $$

**Step 2: Compute the Covariance Matrix**
For a dataset with *n* features, compute an *n × n* covariance matrix. This matrix tells you how every pair of features varies together.

**Step 3: Compute Eigenvalues and Eigenvectors**
Decompose the covariance matrix to get eigenvectors (directions) and eigenvalues (magnitude of variance in that direction).

**Step 4: Sort and Select Top-k Eigenvectors**
Sort eigenvalues in descending order. Pick the top *k* eigenvectors — these become your new axes (Principal Components). *k* is chosen based on how much cumulative variance you want to retain (commonly 90–95%).

**Step 5: Project the Data**
Multiply the original standardized data by the matrix of top-*k* eigenvectors. This gives you the new, reduced-dimension dataset.

$$ Z = X_{standardized} \cdot W_k $$

where $W_k$ is the matrix of top-k eigenvectors.

### 3.4 How to choose the number of components (k)?

Plot the **cumulative explained variance** vs number of components — this is called a **Scree Plot**. Pick the smallest *k* where cumulative variance crosses a threshold (e.g., 95%).

### 3.5 Limitations of PCA

- Only captures **linear** relationships. Fails if data has non-linear structure (e.g., data shaped like two concentric circles).
- Principal components are **hard to interpret** — PC1 might be some weird combination like `0.5*income - 0.3*age + 0.7*spending`, which doesn't have a clean real-world meaning.
- Sensitive to **outliers** (since it's variance-based, and outliers inflate variance).
- Assumes the directions of **maximum variance** are the most important — this isn't always true. Sometimes low-variance directions carry critical signal (e.g., rare fraud patterns).

## 4. Kernel PCA

### 4.1 Definition

**Kernel PCA** is a non-linear extension of PCA. It uses the **kernel trick** to project data into a higher-dimensional space where it *becomes* linearly separable, and then applies regular PCA in that new space.

### 4.2 Core Principle

Sometimes your data isn't separable by a straight line/plane in its original space. Classic example: two concentric circles (one class inside, one class as a ring outside). No straight line can separate them, and no linear PCA projection will help.

**The kernel trick idea**: instead of explicitly transforming data into a higher-dimensional space (which can be computationally very expensive, even infinite-dimensional), we use a **kernel function** that computes the dot product of points *as if* they were in that higher-dimensional space — without ever actually computing the transformation. This is called the **"kernel trick"**.

Common kernels:
- **RBF (Radial Basis Function / Gaussian)**: $K(x, y) = \exp(-\gamma \|x-y\|^2)$ — most popular, captures local similarity.
- **Polynomial**: $K(x, y) = (x^T y + c)^d$
- **Sigmoid**: like a neural network activation function.

### 4.3 Step-by-Step Working of Kernel PCA

**Step 1: Choose a kernel function** (RBF, polynomial, sigmoid, etc.) based on the suspected structure of the data.

**Step 2: Compute the Kernel Matrix (Gram Matrix)**
Instead of a covariance matrix, compute an *n × n* kernel matrix K, where each entry $K_{ij} = K(x_i, x_j)$ represents the "similarity" between points i and j in the higher-dimensional space.

**Step 3: Center the Kernel Matrix**
Since we can't literally subtract the mean in an unknown high-dimensional space, there's a mathematical trick to center the kernel matrix directly:

$$ K_{centered} = K - 1_n K - K 1_n + 1_n K 1_n $$

(where $1_n$ is an *n × n* matrix with all values = 1/n)

**Step 4: Compute Eigenvalues and Eigenvectors of the Centered Kernel Matrix**
Same idea as PCA, but now applied to the kernel matrix instead of the covariance matrix.

**Step 5: Select Top-k Eigenvectors and Project**
Just like PCA — pick the top-k eigenvectors (based on eigenvalues) and use them to get the reduced-dimension representation.

### 4.4 PCA vs Kernel PCA — Quick Comparison

| Aspect | PCA | Kernel PCA |
|---|---|---|
| Relationship captured | Linear only | Non-linear |
| Based on | Covariance matrix | Kernel (Gram) matrix |
| Interpretability | Slightly easier | Harder |
| Computational cost | Cheaper, scales well | Expensive (kernel matrix is n×n, grows with data size) |
| Choosing hyperparameters | Just choose k | Choose k, kernel type, and kernel parameters (like gamma) |
| Can it invert back to original space? | Yes (approximately) | Not directly — needs "pre-image" approximation |

## 5. Linear Discriminant Analysis (LDA)

### 5.1 Definition

**LDA** is a **supervised** linear dimensionality reduction technique. Unlike PCA, it uses **class labels** to find the projection that best **separates classes**, not just the direction of maximum variance.

### 5.2 Core Principle

PCA asks: *"Which direction has the most spread?"*
LDA asks: *"Which direction best separates my classes?"*

LDA tries to find a projection where:
- **Between-class variance is maximized** (classes are pushed far apart from each other), and
- **Within-class variance is minimized** (points within the same class are pulled close together).

This is captured in the famous **Fisher's criterion**:

$$ J(w) = \frac{w^T S_B w}{w^T S_W w} $$

where:
- $S_B$ = Between-class scatter matrix (spread *between* class means)
- $S_W$ = Within-class scatter matrix (spread *within* each class)

We want to find the direction *w* that maximizes this ratio — maximum separation between classes, minimum spread within each class.

**Analogy**: Imagine you're trying to separate apples and oranges on a table by pushing them along one direction with a ruler. LDA finds the angle of the ruler where apples cluster tightly on one side and oranges cluster tightly on the other side, with the biggest possible gap between the two clusters.

### 5.3 Step-by-Step Working of LDA

**Step 1: Compute the mean vector for each class**, and the overall mean of the dataset.

**Step 2: Compute the Within-Class Scatter Matrix ($S_W$)**
This measures how much data points within each class vary around their own class mean. Summed across all classes.

$$ S_W = \sum_{c} \sum_{i \in c} (x_i - \mu_c)(x_i - \mu_c)^T $$

**Step 3: Compute the Between-Class Scatter Matrix ($S_B$)**
This measures how far apart the class means are from the overall mean.

$$ S_B = \sum_{c} n_c (\mu_c - \mu)(\mu_c - \mu)^T $$

**Step 4: Solve the Generalized Eigenvalue Problem**
Compute eigenvectors and eigenvalues of $S_W^{-1} S_B$. This gives directions that maximize the between-class to within-class variance ratio.

**Step 5: Select Top Linear Discriminants**
Sort eigenvectors by eigenvalues (descending), pick the top ones. **Important constraint**: if you have *C* classes, you can get at most **C − 1** discriminant components (this is a very common interview trick question — see below).

**Step 6: Project the Data**
Multiply original data by the selected eigenvectors to get the reduced, class-separated dataset.

### 5.4 PCA vs LDA — Quick Comparison

| Aspect | PCA | LDA |
|---|---|---|
| Learning type | Unsupervised | Supervised (needs labels) |
| Goal | Maximize variance | Maximize class separability |
| Max components | min(n_features, n_samples) | C − 1 (C = number of classes) |
| Use case | General compression, visualization, noise reduction | Classification tasks, especially as a preprocessing step |
| Sensitive to class labels | No | Yes |
| Can be used for unlabeled data | Yes | No |

## 6. Simple, Illustrative Code Example

The example below uses the classic **Iris dataset** (3 flower species, 4 features) to compare PCA, Kernel PCA, and LDA side by side.

```python
import numpy as np
import matplotlib.pyplot as plt
from sklearn.datasets import load_iris
from sklearn.preprocessing import StandardScaler
from sklearn.decomposition import PCA, KernelPCA
from sklearn.discriminant_analysis import LinearDiscriminantAnalysis as LDA

# 1. Load data
iris = load_iris()
X, y = iris.data, iris.target   # X: 150 samples x 4 features, y: 3 classes

# 2. Standardize (mean=0, std=1) -- crucial for PCA/Kernel PCA
X_scaled = StandardScaler().fit_transform(X)

# 3. Apply PCA -- unsupervised, reduce 4 features -> 2 components
pca = PCA(n_components=2)
X_pca = pca.fit_transform(X_scaled)
print("PCA explained variance ratio:", pca.explained_variance_ratio_)
# e.g. [0.73, 0.23] -> first 2 components capture ~96% of the info

# 4. Apply Kernel PCA -- non-linear, using RBF kernel
kpca = KernelPCA(n_components=2, kernel='rbf', gamma=0.5)
X_kpca = kpca.fit_transform(X_scaled)

# 5. Apply LDA -- supervised, uses class labels y
#    max components = n_classes - 1 = 3 - 1 = 2 for Iris
lda = LDA(n_components=2)
X_lda = lda.fit_transform(X_scaled, y)

# 6. Plot all three side by side
fig, axes = plt.subplots(1, 3, figsize=(15, 4))
for ax, data, title in zip(
    axes, [X_pca, X_kpca, X_lda], ["PCA", "Kernel PCA (RBF)", "LDA"]
):
    scatter = ax.scatter(data[:, 0], data[:, 1], c=y, cmap='viridis', edgecolor='k')
    ax.set_title(title)
    ax.set_xlabel("Component 1")
    ax.set_ylabel("Component 2")

plt.tight_layout()
plt.show()
```

**What you'll typically observe:**
- **PCA**: decent separation because Iris happens to have mostly linear structure, but some overlap between two of the three species (versicolor and virginica are naturally close).
- **Kernel PCA**: can reshape clusters non-linearly; on Iris the improvement over PCA is usually mild since Iris isn't strongly non-linear, but on genuinely non-linear data (like two concentric circles) Kernel PCA shines while PCA fails completely.
- **LDA**: usually shows the *cleanest* class separation of the three, because it directly optimizes for class separability using the labels — which PCA and Kernel PCA never get to see.

## 7. Common and Tricky Interview Questions with Expert Answers

**Q1. What is the fundamental difference between PCA and LDA?**
> PCA is unsupervised and looks for directions of maximum variance, without caring about class labels at all. LDA is supervised and looks for directions that best separate known classes, by maximizing between-class variance while minimizing within-class variance. PCA is about compressing information; LDA is about improving classification.

**Q2. Why do we standardize data before PCA? What happens if we don't?**
> PCA finds directions of maximum variance, and variance depends on scale. If one feature is in the range of thousands (like salary) and another is in single digits (like number of children), the salary feature will dominate the principal components purely because of its scale — not because it's actually more informative. Standardizing puts all features on equal footing (mean 0, std 1) so PCA reflects true correlation structure, not just units of measurement.

**Q3. Can PCA be used for classification directly?**
> Not directly — PCA doesn't know about labels, so it has no notion of "class separability." It's typically used as a *preprocessing* step to reduce dimensions and remove noise/redundancy before feeding data into a classifier (like Logistic Regression, SVM, etc.). It can inadvertently *hurt* classification if the dropped low-variance components actually contained useful class-discriminative information.

**Q4. Why can LDA only produce at most C-1 components, where C is the number of classes?**
> This is a classic "gotcha" question. The between-class scatter matrix $S_B$ is built as a sum of C rank-1 matrices (one per class, each of form $(\mu_c - \mu)(\mu_c - \mu)^T$). Because these C matrices are all "centered" relative to the overall mean, they aren't all independent — one is a linear combination of the others (they must sum in a way that respects the overall mean). This means the rank of $S_B$ is at most C-1, so there can be at most C-1 non-zero eigenvalues, and therefore at most C-1 useful discriminant directions.

**Q5. What is the "kernel trick" and why is it useful?**
> Normally, to make non-linear data linearly separable, you'd need to explicitly map your data into a higher (sometimes infinite) dimensional space, which is computationally very expensive or even impossible to do directly. The kernel trick lets you compute the *dot product* of points as if they were already in that higher-dimensional space, using a kernel function — without ever actually performing the transformation. This makes algorithms like Kernel PCA and SVM able to model non-linear patterns efficiently.

**Q6. Is PCA sensitive to outliers? Why?**
> Yes, quite sensitive. Since PCA is built on variance, and variance is very sensitive to extreme values (squared deviations), a single strong outlier can distort the principal components — the first component might end up pointing toward the outlier direction rather than the true underlying structure of the majority of the data. Robust PCA variants exist specifically to handle this.

**Q7. How do you decide how many principal components to keep?**
> Common approaches: (1) Use a **scree plot** and look for the "elbow" where added components stop giving much extra variance. (2) Pick the smallest k such that cumulative explained variance crosses a threshold, commonly 90-95%. (3) In some pipelines, treat k as a hyperparameter and tune it via cross-validation based on downstream model performance, rather than variance alone.

**Q8. Does PCA guarantee that the top components are the most useful for a downstream prediction task?**
> No — this is a common misconception, and a great thing to bring up in interviews to show depth. PCA only guarantees that the top components capture the most *variance*, not that they're the most *predictive*. It's entirely possible for a low-variance direction to be highly correlated with the target variable, and PCA would happily discard it. This is precisely why LDA (or other supervised techniques) can outperform PCA when the goal is classification.

**Q9. What's the difference between Feature Selection and Feature Extraction?**
> Feature Selection picks a subset of the *original* features and discards the rest (e.g. LASSO regularization, forward/backward selection) — so the remaining features stay interpretable in their original units. Feature Extraction (like PCA/LDA) creates brand-new features that are combinations of the originals — often more powerful for compression, but harder to interpret since a "principal component" doesn't map to a real-world concept directly.

**Q10. Can you apply PCA to categorical data?**
> Not directly in its standard form — PCA relies on variance and covariance, which are defined for continuous numerical data. For categorical data, you'd typically one-hot encode first (though this can blow up dimensionality) or use alternatives designed for categorical/mixed data, like Multiple Correspondence Analysis (MCA) or Factor Analysis of Mixed Data (FAMD).

**Q11. Why does Kernel PCA not give you a simple "explained variance ratio" the way PCA does, and can you always invert it back to the original feature space?**
> Kernel PCA operates on eigenvalues of the kernel matrix, not the true covariance matrix in explicit feature space (which may be infinite-dimensional and never actually computed) — so the "explained variance" doesn't map back to the original features in the same clean way as PCA. As for inversion: since the mapping to higher-dimensional space is implicit, there's no direct formula to reconstruct the original input from its Kernel PCA projection. It requires an approximate technique called "pre-image reconstruction," and even then, it's not exact.

**Q12. In practice, would you use PCA or LDA before a classification model, and why?**
> If the goal is purely dimensionality reduction/compression without hurting classification performance too much, and there's no strong reason to trust the label-driven bias, PCA is a safe, general-purpose default. If class separability is genuinely the goal, and you trust your labels are clean and classes reasonably match Gaussian-ish distributions with similar covariance (LDA's underlying assumption), LDA is usually a stronger preprocessing step because it directly optimizes for what you ultimately care about. In practice, some pipelines use PCA first (to denoise / reduce dimensions) followed by LDA (for class separation) — this combination is fairly common.

**Q13. What assumptions does LDA make about the data?**
> LDA assumes: (1) each class is roughly Gaussian-distributed, (2) all classes share the same covariance matrix (homoscedasticity), and (3) features are not too collinear (since it needs to invert the within-class scatter matrix, which can be singular/unstable if features are highly correlated or if you have more features than samples). Violating these assumptions doesn't mean LDA is unusable, but performance may degrade compared to more flexible methods like QDA (Quadratic Discriminant Analysis) which relaxes the equal-covariance assumption.
