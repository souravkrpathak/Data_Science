# Natural Language Processing

---

## 1. Definition and Fundamental Concepts

**Natural Language Processing (NLP)** is the branch of AI that lets computers read, understand, and generate human language (text or speech).

Human language is messy — same word can mean different things ("bank" of a river vs "bank" for money), grammar has exceptions, and meaning depends on context. NLP is the set of techniques that turns this messy language into numbers a machine can process, and turns machine output back into language.

**Two broad goals of NLP:**
1. **Natural Language Understanding (NLU)** — extracting meaning (e.g., sentiment analysis, intent detection, named entity recognition).
2. **Natural Language Generation (NLG)** — producing language (e.g., summarization, translation, chatbots).

**Why NLP is hard (core challenges):**
- **Ambiguity** — one word/sentence, many meanings.
- **Context dependence** — meaning changes based on surrounding words.
- **Sarcasm/tone** — hard to detect from text alone.
- **Language variety** — slang, typos, multiple languages, dialects.
- **Long-range dependencies** — a pronoun on page 2 may refer to a noun on page 1.

**Typical NLP pipeline (high level):**
```
Raw Text → Text Cleaning/Normalization → Tokenization → Feature 
Representation (BoW/TF-IDF/Embeddings) → Model (ML/DL) → Output
```

---

## 2. Text Processing

Before any model can use text, we must clean and standardize it. This step is called **preprocessing**.

### 2.1 Tokenization
Splitting text into smaller units called **tokens** — usually words, sometimes sentences or sub-words.

- Example: `"I love NLP!"` → `["I", "love", "NLP", "!"]`
- **Word tokenization**: split by words.
- **Sentence tokenization**: split by sentences.
- **Subword tokenization** (used in modern transformers): breaks rare words into smaller known pieces. Examples: **BPE (Byte Pair Encoding)**, **WordPiece**, **SentencePiece**.
  - Why subwords? Handles unknown/rare words gracefully (e.g., "unhappiness" → "un" + "happi" + "ness"), keeps vocabulary size manageable.

### 2.2 Stemming
Cutting words down to a rough "root" form using simple rules (chopping suffixes). Fast but crude — the result may not be a real word.
- Example: `"running"`, `"runs"`, `"runner"` → `"run"` (approx.)
- `"studies"` → `"studi"` (not a real word — this is the downside)
- Common algorithm: **Porter Stemmer**.

### 2.3 Lemmatization
Reduces words to their proper dictionary base form (**lemma**), using vocabulary and grammar rules (part-of-speech aware). Slower than stemming, but more accurate.
- Example: `"running"` → `"run"`, `"better"` → `"good"`, `"studies"` → `"study"`

**Stemming vs Lemmatization (classic interview question):**
| Aspect | Stemming | Lemmatization |
|---|---|---|
| Method | Rule-based chopping | Dictionary + grammar based |
| Speed | Fast | Slower |
| Output | May not be a real word | Always a real word |
| Accuracy | Lower | Higher |
| Example | "studies" → "studi" | "studies" → "study" |

### 2.4 Stop Words
Very common words that carry little unique meaning by themselves — e.g., `"the"`, `"is"`, `"in"`, `"at"`, `"and"`. Often removed to reduce noise and dimensionality in traditional NLP (BoW/TF-IDF).

**Caution:** For tasks like sentiment analysis, words like `"not"` or `"no"` are stop words in some lists but are extremely important (removing "not" flips meaning: "not good" → "good"). Modern deep learning models usually **do not** remove stop words because context matters.

### 2.5 Text Normalization
Standardizing text so variations don't confuse the model. Includes:
- Lowercasing (`"NLP"` → `"nlp"`)
- Removing punctuation, extra whitespace, HTML tags
- Handling contractions (`"don't"` → `"do not"`)
- Spelling correction
- Removing numbers/special characters (task dependent)
- Unicode normalization (handling accented characters, emojis)

## 3. Embeddings vs Text Vectorizers

This is a key conceptual distinction interviewers love to probe.

| | **Traditional Vectorizers (BoW, Count, TF-IDF)** | **Embeddings (Word2Vec, GloVe, Transformers)** |
|---|---|---|
| What it captures | Word **frequency/presence** | Word **meaning and context** |
| Vector size | Size of vocabulary (sparse, huge) | Fixed small size, e.g., 100–768 (dense) |
| Semantic relationships | None ("king" and "queen" unrelated) | Yes (similar words have similar vectors) |
| Sparsity | Mostly zeros (sparse) | Dense, all values meaningful |
| Context awareness | No | Static embeddings: no. Contextual (BERT, GPT): yes |
| Use case | Simple, quick baselines (spam detection) | Deep learning, semantic tasks, modern NLP |

**One-line summary:** Vectorizers count words. Embeddings understand words.

## 4. Bag of Words (BoW)

BoW represents a document as an unordered collection ("bag") of its words, ignoring grammar and word order — only **what** words appear (and how often) matters.

**Steps:**
1. Build a vocabulary of all unique words across all documents.
2. Represent each document as a vector — one number per vocabulary word (count of occurrences).

**Example:**
- Doc 1: "I love NLP"
- Doc 2: "I love Machine Learning"
- Vocabulary: `[I, love, NLP, Machine, Learning]`
- Doc 1 vector: `[1, 1, 1, 0, 0]`
- Doc 2 vector: `[1, 1, 0, 1, 1]`

**Limitations:**
- Ignores word order ("dog bites man" = "man bites dog" in BoW — clearly wrong).
- Very high dimensional and sparse for large vocabularies.
- No sense of word meaning or similarity.

---

## 5. Count Vectorization

This is the practical implementation of BoW (e.g., `CountVectorizer` in scikit-learn). It converts a collection of text documents into a matrix of token counts.

- Rows = documents, Columns = vocabulary words, Values = counts.
- Options: `min_df`/`max_df` (ignore too-rare/too-common words), `ngram_range` (capture word pairs/triples, not just single words), `stop_words='english'`.

**N-grams**: instead of single words ("unigrams"), we can count pairs ("bigrams") or triples ("trigrams") to keep a bit of order/context.
- Unigram: `"not"`, `"good"`
- Bigram: `"not good"` (keeps the negation meaning intact!)

---

## 6. TF-IDF (Term Frequency – Inverse Document Frequency)

BoW/Count Vectorization treats every word as equally important — but common words like "the" get high counts without being informative. **TF-IDF** fixes this by **downweighting words that appear in many documents** and **upweighting words that are frequent in a specific document but rare elsewhere**.

**Formula:**
- **TF (Term Frequency)** = (count of word in document) / (total words in document)
- **IDF (Inverse Document Frequency)** = log( total number of documents / number of documents containing the word )
- **TF-IDF = TF × IDF**

**Intuition:**
- A word appearing in almost every document (like "the") → IDF ≈ 0 → low TF-IDF → not important.
- A word appearing often in one document but rarely elsewhere (like "quantum" in a physics paper) → high TF-IDF → important, distinguishing word.

**Why it's useful:** Great baseline for search engines, document similarity, and simple text classification (spam detection, keyword extraction) — better than raw counts, still doesn't understand meaning.

---

## 7. Skip-gram (and CBOW)

Skip-gram is one of the two training strategies inside **Word2Vec** used to learn word embeddings from raw text, based on the idea: **"a word is defined by the company it keeps"** (the Distributional Hypothesis).

**Skip-gram**: given a **center word**, predict the **surrounding context words**.
- Sentence: `"The quick brown fox jumps"`, center word = `"brown"`, window size = 2
- Task: predict `"quick"`, `"fox"` (and further words within the window) from `"brown"`.
- Good for **rare words** and **small datasets** — because each word gets many training examples (one per context word).

**CBOW (Continuous Bag of Words)**: the opposite — given **context words**, predict the **center word**.
- Given `"quick"`, `"fox"` → predict `"brown"`.
- Faster to train, works better with **frequent words** and **larger datasets**.

**Skip-gram vs CBOW (interview favorite):**
| | Skip-gram | CBOW |
|---|---|---|
| Direction | center → context | context → center |
| Best for | Rare words, small data | Frequent words, large data, speed |
| Training examples per sentence | More (slower) | Fewer (faster) |

## 8. Word Embeddings (General Concept)

A **word embedding** is a dense, fixed-length vector of real numbers that represents a word's meaning, learned so that:
- Similar words have similar (close) vectors — e.g., "king" and "queen" are close in vector space.
- Vector arithmetic can capture relationships: **king − man + woman ≈ queen** (famous example).

Compared to one-hot encoding (a huge sparse vector with a single 1), embeddings are:
- Low-dimensional (e.g., 100–300 dims instead of vocabulary-size dims)
- Dense (every value carries information)
- Capable of capturing semantic similarity

**Types:**
- **Static embeddings**: one fixed vector per word regardless of context — **Word2Vec**, **GloVe**, **FastText**.
- **Contextual embeddings**: vector changes depending on the sentence — **ELMo**, **BERT**, **GPT** (via transformers).

---

## 9. Word2Vec

Word2Vec (Google, 2013) is a shallow neural network method to learn static word embeddings using either **Skip-gram** or **CBOW** (see Section 7).

**How training works (simplified):**
1. Slide a window across a huge text corpus.
2. Train a simple neural network (one hidden layer) to predict context from center word (or vice versa).
3. Throw away the prediction task — keep the **learned hidden-layer weights** as the word vectors (the "byproduct" is the actual goal).

**Key training tricks (often asked in interviews):**
- **Negative Sampling**: instead of updating weights for the entire vocabulary at every step (very expensive), only update weights for the correct word + a small number of randomly sampled "negative" (wrong) words. Massively speeds up training.
- **Hierarchical Softmax**: an alternative speed-up using a binary tree structure over the vocabulary to reduce computation from O(V) to O(log V).

**Limitations of Word2Vec:**
- Static — same vector for a word regardless of context ("bank" always has the same vector, whether it's a river bank or a money bank).
- Cannot handle out-of-vocabulary (OOV) words (unlike FastText, which uses subword/character n-grams).
- Only uses local context window — ignores global co-occurrence statistics.

---

## 10. GloVe (Global Vectors for Word Representation)

GloVe (Stanford, 2014) also produces static word embeddings but uses a different approach than Word2Vec.

**Core idea:** Instead of only looking at local context windows (like Word2Vec), GloVe builds a **global word co-occurrence matrix** across the entire corpus first — "how often does word X appear near word Y across the whole corpus?" — then factorizes/optimizes this matrix into dense vectors such that the **ratio of co-occurrence probabilities** captures meaning.

**Word2Vec vs GloVe (common interview question):**
| | Word2Vec | GloVe |
|---|---|---|
| Approach | Predictive (neural network, local context window) | Count-based (global co-occurrence matrix + matrix factorization) |
| Uses global corpus statistics | No (local windows only) | Yes |
| Training | Online, one window at a time | Batch, on the full co-occurrence matrix |
| Performance | Very good, especially with negative sampling | Very good, especially for capturing broad semantic patterns |

Both produce similar quality static embeddings in practice — the key interview point is: **Word2Vec is prediction-based/local, GloVe is count-based/global**.

## 11. The Transformer Architecture

Introduced in the paper *"Attention Is All You Need"* (2017), the Transformer removed the need for recurrence (RNNs/LSTMs) entirely, relying purely on an **attention mechanism**. This is the backbone of nearly all modern NLP models (BERT, GPT, T5, etc.).

**Why Transformers replaced RNNs/LSTMs:**
- RNNs process words **one at a time, sequentially** → slow, can't parallelize, and struggle with long-range dependencies (vanishing gradients over long sequences).
- Transformers process **all words in parallel** and use attention to directly connect any two words in a sequence, regardless of distance → faster training, better handling of long-range context.

**Key building blocks of a Transformer:**
1. **Input Embeddings** — convert tokens to vectors.
2. **Positional Encoding** — since there's no recurrence, the model has no innate sense of word order, so we add a positional signal (sine/cosine functions or learned vectors) to each embedding so the model knows word position.
3. **Multi-Head Self-Attention** — lets each word "look at" every other word and decide how much to focus on each (details in Section 13).
4. **Feed-Forward Network** — a simple fully connected network applied to each position independently, adding processing power after attention.
5. **Residual Connections + Layer Normalization** — help gradients flow through deep stacks of layers and stabilize training.
6. **Stack of Layers** — the above blocks are repeated N times (e.g., 12, 24, or more layers) to build depth.

---

## 12. Encoder-Decoder Architecture

Many NLP tasks are **sequence-to-sequence** (seq2seq): input is one sequence, output is another (translation, summarization). The classic Transformer paper used an **Encoder-Decoder** structure to handle this.

**Encoder:**
- Reads the entire input sentence and builds a rich contextual representation of it.
- Made of stacked layers of self-attention + feed-forward blocks.
- Every input token can attend to every other input token (bidirectional — sees full sentence at once).

**Decoder:**
- Generates the output sequence one token at a time (e.g., translated sentence), using:
  1. **Masked self-attention** — attends only to previously generated tokens (can't "cheat" by looking at future words it hasn't generated yet).
  2. **Cross-attention (encoder-decoder attention)** — lets the decoder look back at the encoder's output to know what the input sentence said, while generating each output word.
- Made of stacked layers too, typically same count as encoder.

**Example flow (English → French translation):**
```
Input: "I love NLP" → Encoder → contextual representation
Decoder generates: "J'" → "aime" → "le" → "NLP" (one word at a time, 
looking back at encoder output each time)
```

**Which models use which part:**
| Model | Uses | Typical Task |
|---|---|---|
| **BERT** | Encoder only | Understanding tasks (classification, NER, QA) |
| **GPT** | Decoder only | Generation tasks (text completion, chat) |
| **T5 / original Transformer** | Encoder + Decoder | Translation, summarization |

## 13. Attention Mechanism (Query, Key, Value)

Attention is the mathematical trick that lets a model decide **"which other words should I pay attention to, and how much?"** for every word in a sequence.

**The intuition:** Imagine reading the sentence "The animal didn't cross the street because **it** was too tired." To understand what "it" refers to, you (a human) automatically look back at "animal" — you pay more *attention* to that word than to "street". Attention lets the model do this automatically and mathematically.

**Query, Key, Value (Q, K, V) — the core idea:**
For every word, we create three vectors (by multiplying the word's embedding with three learned weight matrices):
- **Query (Q)** — represents "what am I looking for?" (like a search query)
- **Key (K)** — represents "what do I contain / what can I offer?" (like a label on a piece of information)
- **Value (V)** — represents "the actual content/information to be passed along if selected"

**Steps (Scaled Dot-Product Attention):**
1. For a given word's Query, compute its **dot product with every word's Key** → gives a raw similarity/relevance score for each pair of words.
2. **Scale** the scores by dividing by √(dimension of key vectors) — keeps gradients stable, prevents very large values from dominating.
3. Apply **softmax** to turn scores into probabilities that sum to 1 (these are the **attention weights** — "how much to focus on each word").
4. Multiply each word's **Value** by its attention weight, and sum them all up → this weighted sum is the output for that word — a blend of relevant information from the whole sequence.

**Formula:**
```
Attention(Q, K, V) = softmax( (Q · Kᵀ) / √d_k ) · V
```

**Simple analogy (library search):**
- Query = your search term at a library desk.
- Key = the label/index card on each book describing what it's about.
- Value = the actual content inside the book.
- You compare your Query to every book's Key to find relevance, then you read (weight) the Value of the most relevant books the most.

**Self-Attention vs Cross-Attention:**
- **Self-attention**: Q, K, V all come from the **same** sequence (word attends to other words in the same sentence).
- **Cross-attention**: Q comes from the decoder, K and V come from the encoder output (decoder word "looks at" the input sentence).

**Multi-Head Attention:**
Instead of doing attention once, the Transformer does it **multiple times in parallel** ("heads"), each with its own learned Q/K/V weight matrices. Each head can learn to focus on a different type of relationship (e.g., one head might focus on syntax/grammar links, another on coreference like "it" → "animal"). The outputs of all heads are concatenated and projected back to the original size.

**Why attention is powerful (interview key point):**
- Handles long-range dependencies directly (distance between words doesn't matter — unlike RNNs where information must pass through every intermediate step).
- Fully parallelizable (unlike RNNs' sequential nature) → much faster training on GPUs.
- Gives interpretability — attention weights can be visualized to see what the model is "focusing on".

## 14. Other Important NLP Topics

### 14.1 Named Entity Recognition (NER)
Identifying and classifying real-world entities in text (person, organization, location, date, etc.). Example: "**Sourav** works at **Citi** in **Bengaluru**" → Person, Organization, Location.

### 14.2 Part-of-Speech (POS) Tagging
Labeling each word with its grammatical role (noun, verb, adjective, etc.). Useful for lemmatization and parsing.

### 14.3 Language Models & Perplexity
A **language model** predicts the probability of a sequence of words (or the next word given previous words). **Perplexity** measures how "surprised" a model is by test data — lower perplexity = better model (it predicted the actual words with higher confidence).

### 14.4 Sequence Models Before Transformers (RNN, LSTM, GRU)
- **RNN**: processes sequences step by step, keeping a "hidden state" memory — but suffers from vanishing/exploding gradients on long sequences.
- **LSTM (Long Short-Term Memory)**: adds gates (input, forget, output) to control what information to keep or discard — handles longer sequences much better than plain RNNs.
- **GRU (Gated Recurrent Unit)**: a simplified LSTM with fewer gates, faster to train, similar performance in many tasks.

### 14.5 Transfer Learning in NLP: Pretraining + Fine-tuning
Modern NLP follows a two-stage recipe:
1. **Pretraining**: train a large model (like BERT/GPT) on massive unlabeled text using self-supervised tasks (e.g., predict masked words, predict next word).
2. **Fine-tuning**: adapt the pretrained model to a specific task (sentiment analysis, Q&A) using a smaller labeled dataset.

This is why models like BERT and GPT are so powerful — they already "know" language structure before ever seeing your specific task.

### 14.6 BERT vs GPT (common interview comparison)
| | BERT | GPT |
|---|---|---|
| Architecture | Encoder only | Decoder only |
| Attention direction | Bidirectional (sees full sentence, both directions) | Unidirectional / autoregressive (left-to-right only) |
| Pretraining task | Masked Language Modeling (predict hidden/masked words) + Next Sentence Prediction | Next-word prediction (causal language modeling) |
| Best suited for | Understanding tasks (classification, NER, extractive QA) | Generation tasks (text completion, chat, creative writing) |

### 14.7 Tokenization for Modern LLMs: BPE / WordPiece / SentencePiece
Modern models don't use whole-word vocabularies (too large, can't handle new words). Instead they use **subword tokenization**:
- **BPE (Byte Pair Encoding)**: iteratively merges the most frequent pair of characters/subwords into new tokens.
- **WordPiece**: similar to BPE but merges based on likelihood improvement (used in BERT).
- **SentencePiece**: works directly on raw text (including spaces) without needing pre-tokenized words — language agnostic (used in T5, LLaMA).

### 14.8 Evaluation Metrics in NLP
- **Classification tasks**: Accuracy, Precision, Recall, F1-score.
- **Machine Translation**: **BLEU score** (compares generated text n-grams to reference translations).
- **Summarization**: **ROUGE score** (measures overlap of generated summary with reference summary).
- **Language Models**: **Perplexity**.

### 14.9 RAG (Retrieval-Augmented Generation)
Combines a retrieval system (like a vector database with embeddings, e.g., FAISS) with a generative LLM: relevant documents are retrieved based on the query's embedding similarity, then fed into the LLM as context so it can generate grounded, up-to-date, and factual answers instead of relying only on what it memorized during training. Very relevant for enterprise LLM applications (e.g., evaluation pipelines over transcripts/documents).

### 14.10 Cosine Similarity
The standard way to measure how "similar" two embedding vectors are — measures the angle between vectors rather than magnitude:
```
cosine_similarity(A, B) = (A · B) / (‖A‖ × ‖B‖)
```
Value ranges from -1 (opposite) to 1 (identical direction/meaning). Used heavily in semantic search, RAG retrieval, and clustering similar documents.

## 15. Simple Illustrative Code Example

This example shows the classic NLP pipeline progression: **preprocessing → BoW → TF-IDF → Word2Vec embeddings → cosine similarity**, using simple, well-known libraries.

```python
# pip install nltk scikit-learn gensim --quiet

import nltk
nltk.download('punkt')
nltk.download('stopwords')
nltk.download('wordnet')

from nltk.tokenize import word_tokenize
from nltk.corpus import stopwords
from nltk.stem import WordNetLemmatizer
from sklearn.feature_extraction.text import CountVectorizer, TfidfVectorizer
from gensim.models import Word2Vec
from numpy import dot
from numpy.linalg import norm

# ---------- 1. Sample Corpus ----------
corpus = [
    "I love natural language processing",
    "I love machine learning",
    "NLP and machine learning are exciting fields"
]

# ---------- 2. Text Preprocessing ----------
lemmatizer = WordNetLemmatizer()
stop_words = set(stopwords.words('english'))

def preprocess(text):
    tokens = word_tokenize(text.lower())               # tokenization + lowercase
    tokens = [t for t in tokens if t.isalpha()]         # remove punctuation/numbers
    tokens = [t for t in tokens if t not in stop_words] # remove stop words
    tokens = [lemmatizer.lemmatize(t) for t in tokens]  # lemmatization
    return tokens

processed_corpus = [preprocess(doc) for doc in corpus]
print("Processed tokens:", processed_corpus)

# ---------- 3. Bag of Words (Count Vectorization) ----------
count_vec = CountVectorizer()
bow_matrix = count_vec.fit_transform(corpus)
print("\nVocabulary:", count_vec.get_feature_names_out())
print("BoW matrix:\n", bow_matrix.toarray())

# ---------- 4. TF-IDF ----------
tfidf_vec = TfidfVectorizer()
tfidf_matrix = tfidf_vec.fit_transform(corpus)
print("\nTF-IDF matrix:\n", tfidf_matrix.toarray().round(2))

# ---------- 5. Word2Vec Embeddings (Skip-gram) ----------
w2v_model = Word2Vec(
    sentences=processed_corpus,
    vector_size=50,   # embedding dimension
    window=3,         # context window size
    min_count=1,
    sg=1              # sg=1 -> Skip-gram; sg=0 -> CBOW
)

vector_nlp = w2v_model.wv['nlp']
print("\nEmbedding for 'nlp' (first 5 dims):", vector_nlp[:5])

# ---------- 6. Cosine Similarity Between Word Embeddings ----------
def cosine_sim(a, b):
    return dot(a, b) / (norm(a) * norm(b))

sim = cosine_sim(w2v_model.wv['nlp'], w2v_model.wv['machine'])
print(f"\nCosine similarity between 'nlp' and 'machine': {sim:.3f}")
```

**What this demonstrates:**
- Cleaning raw text into usable tokens.
- Two classic sparse representations (BoW, TF-IDF).
- A dense embedding representation (Word2Vec) trained directly on the toy corpus.
- How embeddings let us mathematically measure word similarity — something BoW/TF-IDF can never do.

## 16. Interview Questions & Expert Answers

### Q1. What is the difference between stemming and lemmatization? When would you use one over the other?
**A:** Stemming chops word endings using fixed rules, fast but can produce non-words (e.g., "studi"). Lemmatization uses vocabulary and grammar (part-of-speech) to return a real dictionary word (e.g., "study"). Use stemming when speed matters more than precision (e.g., search engines, large-scale indexing). Use lemmatization when the output needs to be readable/interpretable or feeds into a task sensitive to correct word forms.

### Q2. Why do we remove stop words, and when should we NOT remove them?
**A:** Stop words like "the", "is", "in" appear frequently but carry little discriminative meaning, so removing them reduces noise and dimensionality — helpful for BoW/TF-IDF-based classification. However, for sentiment analysis or tasks where negation matters ("not good"), removing words like "not" can flip meaning and hurt accuracy. Modern deep learning/transformer models generally keep all words since they use full context anyway.

### Q3. What are the limitations of Bag of Words / TF-IDF compared to embeddings?
**A:** BoW and TF-IDF ignore word order and semantic meaning — "good" and "great" are treated as completely unrelated dimensions, and vectors are huge and sparse (size = vocabulary). Embeddings solve this by learning dense, low-dimensional vectors where semantically similar words are close together, and they generalize better to unseen word combinations.

### Q4. Explain how TF-IDF actually down-weights common words. Walk through the math intuition.
**A:** TF measures how often a word appears within one document (local importance). IDF = log(total documents / documents containing the word) — if a word appears in almost every document, this ratio approaches 1, and log(1) = 0, driving IDF (and hence TF-IDF) toward zero. So common words across the corpus get suppressed, while words specific to few documents get amplified when they do appear.

### Q5. Difference between Skip-gram and CBOW — which would you pick for a small dataset with rare technical terms?
**A:** Skip-gram predicts context words from a center word, generating multiple training pairs per sentence — this gives rare words more training signal, making Skip-gram better suited for small datasets or vocabularies with rare/technical terms. CBOW predicts the center word from context, trains faster, and works well with large datasets and frequent words, since it effectively averages/smooths over context.

### Q6. Why does Word2Vec use Negative Sampling? What problem does it solve?
**A:** Without negative sampling, every training step would require updating the output weights for the entire vocabulary (which could be hundreds of thousands of words) via a full softmax — extremely expensive. Negative sampling reframes it as a set of binary classification problems: distinguish the true context word from a handful of randomly sampled "negative" (incorrect) words, updating only those weights. This makes training dramatically faster while still learning good embeddings.

### Q7. Word2Vec vs GloVe — what's fundamentally different about how they're trained?
**A:** Word2Vec is a predictive, local-context model — it slides a window across text and trains a small neural network to predict nearby words. GloVe is a count-based, global model — it first builds a full word co-occurrence matrix across the entire corpus, then factorizes it so that vector differences reflect co-occurrence probability ratios. In short: Word2Vec learns from local windows one at a time; GloVe learns from global corpus-wide statistics all at once.

### Q8. What is the biggest limitation of Word2Vec/GloVe that Transformers solve?
**A:** Word2Vec and GloVe produce static embeddings — one fixed vector per word regardless of context, so "bank" has the same vector whether it means a riverbank or a financial bank. Transformer-based models (BERT, GPT) produce contextual embeddings — the vector for "bank" changes depending on the surrounding sentence, because self-attention lets the representation absorb context dynamically.

### Q9. Explain the role of Query, Key, and Value in self-attention using an intuitive analogy.
**A:** Think of it like a library search: the Query is your search request, the Key is the label/index card on every book describing its content, and the Value is the actual content inside each book. You compare your Query against every book's Key to get a relevance score, then read the Value of each book weighted by how relevant it is. Mathematically: take the dot product of Query with all Keys, scale by √d_k, apply softmax to get attention weights, then compute a weighted sum of Values — this gives each word a representation that blends in relevant information from the rest of the sequence.

### Q10. Why do we scale the dot product by √d_k in attention (the "scaled" in scaled dot-product attention)?
**A:** As the dimensionality (d_k) of the Query/Key vectors grows, the dot products tend to grow large in magnitude. Very large values pushed through softmax produce extremely peaked distributions (near one-hot), which causes vanishing gradients during backpropagation and unstable training. Dividing by √d_k keeps the values in a reasonable range, so softmax outputs stay well-distributed and gradients flow properly.

### Q11. Why don't Transformers need recurrence, and what do they use instead to capture word order?
**A:** Transformers process the entire sequence in parallel using self-attention, which directly connects any two positions in a single step (no need to pass information step-by-step like RNNs). Since parallel processing removes any inherent notion of order, Transformers add **positional encodings** (fixed sine/cosine patterns or learned vectors) to each token's embedding, giving the model information about each word's position in the sequence.

### Q12. Explain the difference between self-attention and cross-attention in an encoder-decoder Transformer.
**A:** Self-attention happens within a single sequence — Query, Key, and Value all come from the same set of tokens (e.g., encoder tokens attending to other encoder tokens, or decoder tokens attending to earlier decoder tokens). Cross-attention happens between two different sequences — in the decoder, the Query comes from the decoder's current state, while Key and Value come from the encoder's output, letting the decoder "look back" at the full input sentence while generating each output token.

### Q13. Why does the decoder use masked self-attention but the encoder doesn't?
**A:** The encoder needs to build a full understanding of the input sentence, so every token is allowed to attend to every other token in both directions (bidirectional). The decoder, however, generates output one token at a time and must not be allowed to "peek" at future tokens it hasn't generated yet — otherwise it would trivially cheat during training. Masking blocks attention to future positions, forcing the decoder to predict each word only from previously generated words and the encoder's context.

### Q14. What's the difference between BERT and GPT in terms of architecture and use case?
**A:** BERT uses only the Transformer's encoder and is trained bidirectionally (it sees the whole sentence at once) using masked language modeling — this makes it excellent at understanding tasks like classification, NER, and extractive question answering, but it's not naturally suited for text generation. GPT uses only the decoder, trained autoregressively (left-to-right, predicting the next word), making it naturally suited for generation tasks like chat, completion, and creative writing.

### Q15. What is multi-head attention, and why not just use one attention head?
**A:** A single attention head learns one type of relationship between words (e.g., just syntactic dependency). Multi-head attention runs several attention operations in parallel, each with its own learned Q/K/V projection matrices, so different heads can specialize — one might capture grammar/syntax, another might capture coreference (like "it" referring back to "animal"), another might capture topical similarity. Their outputs are concatenated and projected back to the model's dimension, giving a richer combined representation than a single head could provide.

### Q16. In a RAG (Retrieval-Augmented Generation) system, why do we use embeddings and cosine similarity instead of keyword search like TF-IDF?
**A:** Keyword-based search (TF-IDF/BoW) only matches exact or overlapping words, so it misses semantically related but differently worded queries (e.g., "car" vs "automobile"). Embeddings capture meaning, so a query and a relevant document can have high cosine similarity even without shared exact words. This makes retrieval far more robust for real-world queries where users phrase things differently than the source documents — which is exactly why RAG pipelines (e.g., FAISS-based vector search) use dense embeddings rather than sparse TF-IDF vectors for retrieval.

### Q17. What is perplexity, and why is lower perplexity better?
**A:** Perplexity measures how well a probability model predicts a sample — practically, it reflects how "confused" or "surprised" the model is by the actual next words in test data. A lower perplexity means the model assigned higher probability to the correct words, i.e., it modeled the language more accurately. It's essentially an exponentiated form of the cross-entropy loss used to train language models.

### Q18. How would you handle an out-of-vocabulary (OOV) word with Word2Vec vs with a subword-based tokenizer (BPE/WordPiece)?
**A:** Word2Vec assigns one vector per whole word learned during training — if a word was never seen during training, Word2Vec has no vector for it at all (a hard failure), unless you fall back to something like FastText, which represents words as a sum of character n-grams and so can construct an approximate vector even for unseen words. Subword tokenizers (BPE/WordPiece), used in Transformers, avoid this problem entirely by breaking any unknown word into smaller known subword pieces (e.g., "unhappiness" → "un" + "happi" + "ness"), so there is effectively no true OOV problem at the token level.

### Q19. If you had to choose between fine-tuning a pretrained Transformer vs building a TF-IDF + classical ML model for a text classification task, what factors would drive your decision?
**A:** Key factors: (1) **Data size** — with very little labeled data, a pretrained Transformer (leveraging transfer learning) usually outperforms a TF-IDF model trained from scratch; with abundant labeled data, a simpler TF-IDF + logistic regression/SVM can be a strong, fast, interpretable baseline. (2) **Latency/compute budget** — TF-IDF models are far cheaper and faster to serve at scale. (3) **Need for semantic understanding** — if the task depends on nuanced context or paraphrasing, Transformers win. (4) **Interpretability requirements** — TF-IDF/classical models are easier to explain (important in regulated domains like banking/finance). In practice, a good approach is to start with a TF-IDF baseline for a quick benchmark, then justify the added complexity of a Transformer only if it meaningfully beats that baseline.

### Q20. Explain the vanishing gradient problem in RNNs and how attention-based Transformers avoid it.
**A:** In RNNs, information from early time steps must pass through many sequential multiplications (through the hidden state) to influence later steps; during backpropagation through time, gradients for long sequences can shrink exponentially (vanish) or blow up (explode), making it hard to learn long-range dependencies. Transformers avoid this entirely because self-attention connects any two positions in the sequence directly, in a single step, regardless of their distance — there's no long chain of sequential operations for the gradient to pass through, so long-range dependencies are learned just as easily as short-range ones.
